## 二、质量标准概述

一个高质量的资源包应当在以下五个维度上达到合格标准。这些维度不是独立的，它们相互关联、相互制约。

### 2.1 结构规范性

**核心原则：遵循 Minecraft 的目录约定，不引入冗余或错放的文件。**

一个结构规范的资源包应当：

- 根目录包含 `pack.mcmeta`，可选 `pack.png`（推荐 128x128 或 256x256 PNG）
- 所有资源放在 `assets/<命名空间>/` 下，命名空间使用小写字母、数字、下划线和连字符
- 目录层级与 Minecraft 原版结构一致，不随意创建非标准子目录
- 避免在根目录放置与资源包无关的文件（如 `.txt` 说明、`.psd` 源文件）

**反面示例：**

```text
MyResourcePack/
  README.md              <-- 不应放在这里
  textures/              <-- 缺少 assets/<namespace>/ 层级
  pack.mcmeta
  .git/                  <-- 不应包含版本控制目录
```

**正面示例：**

```text
MyResourcePack/
  pack.mcmeta
  pack.png
  assets/
    mypack/
      textures/
        block/
          stone.png
        item/
          diamond_sword.png
      models/
        block/
          stone.json
```

**检查清单：**

- [ ] `pack.mcmeta` 存在且 JSON 格式正确
- [ ] `pack_format` 与目标游戏版本匹配
- [ ] 目录结构与 `assets/<namespace>/` 规范一致
- [ ] 无游离文件（如 `.DS_Store`、`Thumbs.db`、`.git` 目录）
- [ ] 命名空间不含大写字母或特殊字符

---

### 2.2 命名一致性

**核心原则：文件名和路径在整个资源包内保持统一的命名风格。**

命名一致性直接影响可维护性。当用户或协作者打开你的资源包时，他们应该能通过文件名预测文件内容。

**命名规范建议：**

| 场景 | 推荐风格 | 示例 |
|---|---|---|
| 纹理文件 | 小写 + 下划线 | `stone_bricks.png` |
| 模型文件 | 小写 + 下划线，与方块/物品 ID 对齐 | `stone_bricks.json` |
| 自定义资源 | 命名空间前缀 + 描述 | `mypack_custom_sky.png` |
| 声音文件 | 小写 + 下划线 | `ambient_cave.ogg` |
| 语言文件 | 标准 locale 代码 | `zh_cn.json`、`en_us.json` |

**常见命名问题：**

1. **大小写混用**：`Stone.png` 与 `stone.png` 在 Windows 上不区分，在 Linux/macOS 上会冲突
2. **空格与特殊字符**：`my texture.png` 会导致路径解析问题
3. **命名空间污染**：使用 `minecraft` 命名空间覆盖原版资源时，应明确标注覆盖意图
4. **版本号混入文件名**：避免 `stone_v2.png`，应通过版本控制管理迭代

**检查清单：**

- [ ] 所有文件名使用小写字母
- [ ] 多词连接使用下划线而非空格或连字符（或反之，保持统一）
- [ ] 自定义资源带命名空间前缀，避免与其他资源包冲突
- [ ] 目录名与文件名风格一致

---

### 2.3 性能友好性

**核心原则：在视觉效果与运行时性能之间取得平衡，不给客户端造成不必要的负担。**

资源包的性能影响主要体现在三个方面：加载时间、显存占用和运行时帧率。

**关键性能指标：**

| 指标 | 影响因素 | 建议阈值 |
|---|---|---|
| 加载时间 | 文件数量、总大小 | 首次加载 < 5 秒（常规包） |
| 显存占用 | 纹理分辨率与数量 | 16x 包 < 100MB，32x 包 < 200MB |
| 帧率影响 | 模型复杂度、着色器 | 不应导致 >10% 帧率下降 |

**优化策略：**

1. **纹理尺寸选择**
   - 16x：原版风格，性能最优，兼容性最广
   - 32x：常见高质量选择，性能影响可控
   - 64x 及以上：仅在必要时使用，需要考虑目标用户硬件

2. **纹理图集利用**
   - 使用 `atlases/` 目录定义纹理图集，减少纹理切换次数
   - 将频繁共现的纹理放入同一图集

3. **模型简化**
   - 避免不必要的面数（原版方块模型通常 < 12 个面）
   - 使用 `shade: false` 减少着色计算（适用于自发光元素）
   - 对不可见面进行剔除

4. **声音文件优化**
   - 使用 OGG Vorbis 格式（Minecraft 原生支持）
   - 采样率建议 44100Hz，对于环境音可降至 22050Hz
   - 避免过长的音频文件（循环音效应包含干净的循环点）

5. **着色器谨慎使用**
   - 自定义着色器应提供降级方案
   - 测试不同 GPU 的兼容性

**检查清单：**

- [ ] 纹理分辨率在目标范围内
- [ ] 无不必要的超大纹理（如 512x 的普通方块）
- [ ] 模型面数合理
- [ ] 声音文件已压缩至合理大小
- [ ] 着色器有兼容性说明

---

### 2.4 兼容性考虑

**核心原则：明确声明兼容范围，主动处理与其他资源包或模组的冲突。**

兼容性问题通常来自三个方面：游戏版本、模组扩展和资源包叠加。

**版本兼容性：**

```json
{
  "pack": {
    "pack_format": 34,
    "description": "My Resource Pack",
    "supported_formats": {
      "min_inclusive": 34,
      "max_inclusive": 46
    }
  }
}
```

- 使用 `supported_formats`（或 `min_format`/`max_format`）声明兼容的格式版本区间
- 关注 Minecraft 版本更新时的格式变更（如新目录、新 JSON 字段）
- 在 README 中明确标注支持的游戏版本

**模组兼容性：**

| 模组类型 | 兼容策略 |
|---|---|
| OptiFine | 使用 `optifine/` 目录结构，提供 CEM 模型或自定义着色器 |
| Iris | 着色器包应同时支持 OptiFine 和 Iris 格式 |
| Sodium | 纹理图集定义可能与 Sodium 优化冲突，需测试 |
| 模组资源 | 使用独立命名空间，不覆盖模组的 `assets/<modid>/` |

**资源包叠加兼容性：**

- 覆盖原版资源时，使用 `minecraft` 命名空间
- 自定义资源使用独立命名空间
- 语言文件采用键覆盖策略（只覆盖需要修改的键，不复制整个文件）
- 考虑用户同时使用多个资源包的场景

**检查清单：**

- [ ] `pack_format` 已正确设置
- [ ] `supported_formats` 范围合理
- [ ] README 标注了支持的游戏版本
- [ ] 模组兼容性已测试或声明
- [ ] 不与其他常见资源包产生严重冲突

---

### 2.5 文档完整性

**核心原则：好的资源包不仅有好的资源，还有好的说明。**

文档是用户理解、安装和使用资源包的桥梁。缺乏文档的资源包会增加用户困惑和维护成本。

**必备文档要素：**

1. **README.md**
   - 资源包名称与简介
   - 支持的游戏版本
   - 安装说明
   - 主要功能列表
   - 截图或预览
   - 已知问题与限制
   - 许可证信息

2. **变更日志（CHANGELOG.md）**
   - 每个版本的变更记录
   - 新增、修改、删除的资源
   - 兼容性变更说明

3. **许可证（LICENSE）**
   - 明确授权范围（CC BY-NC-SA 4.0 是资源包常见选择）
   - 是否允许二次分发
   - 是否允许商业使用

**可选但推荐：**

- 安装视频教程链接
- 常见问题解答（FAQ）
- 模组兼容性列表
- 贡献指南

**检查清单：**

- [ ] README.md 存在且内容完整
- [ ] 包含支持的游戏版本信息
- [ ] 包含安装说明
- [ ] 许可证已声明
- [ ] 有截图或预览图
- [ ] 变更日志已维护

## 三、资源包质量评估维度

在实际开发和审查资源包时，可以使用以下评估框架对资源包进行系统化评分。每个维度按 1-5 分评估，3 分为合格线。

### 3.1 评估维度总览

```text
                    5 ┌─────────────────────────────────────┐
                      │                                     │
                  4   │    结构规范性 ●                      │
                      │              \                       │
              3       │               \    ● 命名一致性       │
                      │                \  /                  │
          2           │                 ●                    │
                      │                / \                   │
      1               │    ● 兼容性   /   \  ● 性能友好性     │
                      │              /     \                 │
                  0   │    ● 文档完整性                    ● │
                      │                                     │
                      └─────────────────────────────────────┘
```

### 3.2 详细评分标准

#### 结构规范性（权重：25%）

| 分数 | 标准 |
|---|---|
| 5 | 完全符合 Minecraft 目录规范，无冗余文件，命名空间清晰 |
| 4 | 基本规范，有 1-2 处小问题（如多余的 `.txt` 文件） |
| 3 | 结构可识别但有明显不规范处（如目录层级错误） |
| 2 | 结构混乱，难以识别资源包意图 |
| 1 | 缺少 `pack.mcmeta` 或目录结构完全错误 |

#### 命名一致性（权重：20%）

| 分数 | 标准 |
|---|---|
| 5 | 所有文件命名风格统一，与原版 ID 对齐，无歧义 |
| 4 | 大部分一致，有少量风格不统一 |
| 3 | 存在多种命名风格混用 |
| 2 | 命名混乱，难以通过文件名判断内容 |
| 1 | 无命名规律，含大量特殊字符或空格 |

#### 性能友好性（权重：20%）

| 分数 | 标准 |
|---|---|
| 5 | 纹理尺寸合理，模型优化，加载快，帧率影响极小 |
| 4 | 整体合理，个别资源可进一步优化 |
| 3 | 性能影响可接受，但有明显优化空间 |
| 2 | 存在性能问题（如过多高分辨率纹理） |
| 1 | 严重性能问题，导致明显卡顿或加载缓慢 |

#### 兼容性考虑（权重：20%）

| 分数 | 标准 |
|---|---|
| 5 | 明确声明版本范围，测试了常见模组兼容性，处理了叠加冲突 |
| 4 | 版本信息完整，主要兼容性已考虑 |
| 3 | 有基本版本信息，但未测试模组兼容 |
| 2 | 版本信息模糊，存在已知兼容性问题 |
| 1 | 无版本信息，与其他资源包严重冲突 |

#### 文档完整性（权重：15%）

| 分数 | 标准 |
|---|---|
| 5 | README、CHANGELOG、LICENSE 齐全，有截图和安装说明 |
| 4 | 核心文档齐全，缺少可选文档 |
| 3 | 有 README 但内容简略 |
| 2 | 仅有简单说明或无说明 |
| 1 | 无任何文档 |

## 四、推荐的开发工作流程

以下工作流程适用于从零开始创建一个资源包，也适用于对现有资源包的迭代改进。

### 4.1 阶段一：规划

**目标：明确资源包的范围、目标用户和核心功能。**

1. **定义范围**
   - 资源包类型：纯纹理？模型改造？声音替换？综合型？
   - 目标分辨率：16x / 32x / 64x / 更高？
   - 目标游戏版本：单版本？多版本区间？

2. **分析参考**
   - 研究同类优秀资源包的结构和做法
   - 参考本项目的 [资源包逐个研究](../03-资源包逐个研究/) 章节
   - 了解目标版本的 `pack_format` 和目录变更

3. **制定计划**
   - 列出需要修改的资源清单
   - 确定命名空间（建议使用独立命名空间，避免使用 `minecraft` 除非必要）
   - 规划目录结构

### 4.2 阶段二：搭建骨架

**目标：创建资源包的基础结构，确保游戏能正确识别。**

1. 创建根目录和 `assets/<namespace>/` 结构
2. 编写 `pack.mcmeta`：

```json
{
  "pack": {
    "pack_format": 34,
    "description": "My Resource Pack - A brief description",
    "supported_formats": {
      "min_inclusive": 34,
      "max_inclusive": 46
    }
  }
}
```

3. 添加 `pack.png`（可选但推荐）
4. 在游戏中加载测试，确认资源包被正确识别

### 4.3 阶段三：资源制作

**目标：按模块逐步添加和替换资源。**

推荐按以下顺序推进（从简单到复杂）：

1. **纹理替换** — 最基础，立竿见影
   - 从原版资源中提取目标纹理作为参考
   - 保持相同的文件名和路径
   - 注意 UV 映射与模型的对应关系

2. **模型修改** — 需要理解 JSON 模型语法
   - 从原版模型复制并修改
   - 测试方块状态映射是否正确
   - 注意模型引用的纹理路径

3. **语言文件** — 相对独立，可并行进行
   - 只覆盖需要修改的翻译键
   - 保持 JSON 格式正确，注意转义字符

4. **声音替换** — 需要音频处理工具
   - 使用 OGG Vorbis 格式
   - 保持与原版声音事件的对应关系

5. **高级功能** — 着色器、粒子、字体等
   - 需要更深入的技术知识
   - 建议参考本项目的 [技术深度](../09-技术深度/) 章节

**每个模块完成后，都应在游戏中进行测试。**

### 4.4 阶段四：测试与优化

**目标：确保资源包在各种场景下正常工作。**

1. **功能测试**
   - 加载游戏，确认资源包被正确应用
   - 检查所有修改的方块、物品、实体是否显示正确
   - 测试语言切换是否正常
   - 检查声音是否播放正确

2. **兼容性测试**
   - 测试与其他常用资源包叠加使用
   - 如果声明支持模组，测试模组兼容性
   - 测试不同资源包加载顺序下的行为

3. **性能测试**
   - 对比加载时间（有/无资源包）
   - 观察帧率变化
   - 检查显存占用

4. **边界测试**
   - 测试极端情况（如大量方块同时渲染）
   - 测试多人服务器环境
   - 测试不同操作系统（Windows / macOS / Linux）

### 4.5 阶段五：文档与发布

**目标：完善文档，打包发布。**

1. **编写文档**
   - README.md：名称、简介、版本、安装、截图
   - CHANGELOG.md：版本变更记录
   - LICENSE：许可证声明

2. **打包**
   - 确认目录结构正确
   - 删除无关文件（`.git`、`.psd`、`.txt` 说明等）
   - 打包为 `.zip` 文件（根目录应直接包含 `pack.mcmeta` 和 `assets/`）

3. **发布**
   - 选择发布平台（Modrinth、CurseForge、GitHub 等）
   - 填写版本信息、兼容性标签
   - 上传截图和预览

### 4.6 阶段六：维护与迭代

**目标：根据反馈持续改进，适配新版本。**

1. **监控反馈**
   - 关注评论区的兼容性报告
   - 收集功能请求

2. **版本更新**
   - 跟踪 Minecraft 版本更新
   - 更新 `pack_format` 和 `supported_formats`
   - 适配新版本引入的目录或字段变更

3. **迭代改进**
   - 根据反馈优化性能
   - 修复已知问题
   - 添加新功能

## 五、快速参考卡片

以下是一份可打印的快速参考，适合贴在开发时随时查看。

### 资源包最小可行结构

```text
MyResourcePack/
  pack.mcmeta          <-- 必须
  pack.png             <-- 推荐
  assets/
    mynamespace/       <-- 你的命名空间
      textures/        <-- 纹理资源
      models/          <-- 模型资源
      lang/            <-- 语言文件
```

### pack.mcmeta 最小模板

```json
{
  "pack": {
    "pack_format": 34,
    "description": "资源包描述"
  }
}
```

### pack_format 版本对照（常用）

| Minecraft 版本 | pack_format |
|---|---|
| 1.20.3 - 1.20.4 | 22 |
| 1.20.5 - 1.20.6 | 32 |
| 1.21 - 1.21.1 | 34 |
| 1.21.2 - 1.21.3 | 42 |
| 1.21.4 | 46 |
| 1.21.5+ | 47+（请查阅 Wiki 获取最新值） |

> 注意：`pack_format` 值会随 Minecraft 更新而变化，请始终参考 [Minecraft Wiki](https://minecraft.wiki/w/Pack_format) 获取最新信息。

### 常见错误速查

| 症状 | 可能原因 | 解决方法 |
|---|---|---|
| 资源包不显示 | 缺少 `pack.mcmeta` 或 JSON 格式错误 | 检查文件存在性和 JSON 语法 |
| 纹理显示为紫黑色 | 纹理路径错误或文件名不匹配 | 核对路径与文件名 |
| 模型显示异常 | JSON 模型语法错误或引用了不存在的纹理 | 验证 JSON 结构和纹理引用 |
| 语言不生效 | 语言文件路径错误或 JSON 格式错误 | 检查 `lang/<locale>.json` 路径和内容 |
| 声音不播放 | 声音事件未在 `sounds.json` 中注册 | 检查 `sounds.json` 的事件定义 |
| 游戏崩溃 | 着色器编译错误或模型面数异常 | 移除自定义着色器或简化模型 |
