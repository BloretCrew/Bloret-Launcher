# Minecraft 资源包开发指南 - 总览

## 一、文档定位与目标读者

### 1.1 文档定位

本开发指南是 Minecraft 资源包开发的系统性实践指南，旨在为开发者提供从入门到进阶的完整开发路径。与理论研究文档不同，本指南侧重于实际操作，包含大量代码示例、工具使用说明和最佳实践建议。

本指南涵盖以下核心主题：

- **纹理包开发**：替换和自定义游戏中的各种纹理贴图
- **模型包开发**：创建自定义方块模型、物品模型和实体模型
- **声音包开发**：替换和添加游戏中的各种音效和音乐
- **综合资源包开发**：整合以上各类资源，构建完整的资源包

### 1.2 目标读者

本指南适合以下读者：

| 读者类型 | 适合内容 | 前置知识 |
|---------|---------|---------|
| 初学者 | 纹理替换、基础配置 | 基本的文件操作能力 |
| 有经验的开发者 | 自定义模型、动画系统 | JSON 语法基础 |
| 专业开发者 | 着色器、性能优化 | GLSL 基础、图形学知识 |
| Mod 兼容开发者 | Mod 兼容资源包 | Mod 开发基础 |

### 1.3 版本兼容性说明

本指南主要针对以下 Minecraft 版本编写，但大部分内容适用于 1.14+ 版本：

- **主要版本**：1.20.x - 1.21.x
- **Java 版**：所有内容均基于 Java 版
- **基岩版**：部分概念通用，但文件格式和路径有差异

## 二、开发环境准备

### 2.1 必备软件

#### 文本编辑器

推荐使用以下编辑器之一：

```
推荐配置：
- Visual Studio Code（推荐）
  - 扩展：JSON Support
  - 扩展：Minecraft JSON Schema（提供自动补全）
  - 扩展：Blockbench Model Preview

- 或 Notepad++
```

#### 图像编辑工具

| 工具 | 用途 | 特点 |
|------|------|------|
| Aseprite | 像素画编辑 | 专业像素画工具，支持动画 |
| GIMP | 通用图像编辑 | 免费开源，功能强大 |
| Blockbench | 模型和纹理 | 专为 Minecraft 设计 |
| Paint.NET | 轻量级编辑 | 简单易用，支持图层 |

```
- Audacity（推荐，免费开源）

  - 提供降噪、均衡器等处理功能
- 或 Adobe Audition
- 或 Reaper
```

#### 3D 建模工具

```
- Blockbench（强烈推荐）
  - 专为 Minecraft 模型设计
  - 支持方块模型、物品模型、实体模型
  - 内置纹理绘制功能
  - 导出标准 JSON 格式
```

### 2.2 开发目录结构

建议在开发前建立规范的目录结构：

```
Minecraft-Resourcepacks-Research/
├── docs/                      # 文档目录
│   └── 08-开发指南/            # 本系列文档
├── Resourcepacks/             # 资源包开发目录
│   ├── my-resourcepack/       # 具体资源包项目
│   │   ├── pack.mcmeta        # 资源包元数据
│   │   ├── pack.png           # 资源包图标
│   │   ├── assets/            # 资源文件目录
│   │   │   └── minecraft/     # Minecraft 命名空间
│   │   │       ├── textures/  # 纹理文件
│   │   │       ├── models/    # 模型文件
│   │   │       ├── sounds/    # 声音文件
│   │   │       ├── blockstates/ # 方块状态
│   │   │       ├── lang/      # 语言文件
│   │   │       ├── shaders/   # 着色器
│   │   │       ├── font/      # 字体文件
│   │   │       └── particles/ # 粒子效果
│   │   └── assets/[modid]/    # Mod 命名空间
│   └── templates/             # 模板文件
└── scripts/                   # 辅助脚本
```

### 2.3 Minecraft 安装目录定位

资源包需要放置在 Minecraft 的 `resourcepacks` 目录中：

```
Windows:
%APPDATA%\.minecraft\resourcepacks\

macOS:
~/Library/Application Support/minecraft/resourcepacks/

Linux:
~/.minecraft/resourcepacks/
```

### 2.4 获取原版资源文件

开发时经常需要参考原版资源文件。获取方法：

```bash
# 方法一：从 Minecraft JAR 文件提取
# 1. 找到版本 JAR 文件
# 路径：.minecraft/versions/1.21.x/1.21.x.jar

# 2. 用压缩软件打开，提取 assets 目录
# JAR 文件本质上是 ZIP 格式

# 方法二：使用内置资源包
# 在资源包选择界面，点击"打开资源包文件夹"
# 上方的 "Minecraft" 资源包即为原版资源

# 方法三：使用工具提取
# 推荐使用 MultiMC 或 Prism Launcher 的资源提取功能
```

### 2.5 快速验证环境

创建一个最小资源包来验证开发环境：

```json
// pack.mcmeta - 最小资源包配置文件
{
  "pack": {
    "pack_format": 34,
    "description": "测试资源包"
  }

```

```
目录结构：
test-pack/
├── pack.mcmeta
└── assets/
    └── minecraft/
        └── textures/
            └── block/
                └── stone.png  # 替换为任意 16x16 PNG 图片
```

将此目录压缩为 ZIP 文件（或直接放在 resourcepacks 目录），在游戏中启用后检查石头纹理是否被替换。

## 三、开发工作流程

### 3.1 完整开发流程

资源包开发遵循以下标准流程：

```
┌─────────────────────────────────────────────────────────┐
│                    资源包开发流程                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 规划阶段 ──→ 2. 创建目录 ──→ 3. 配置 pack.mcmeta    │
│       │                              │                  │
│       ↓                              ↓                  │
│  4. 添加资源 ──→ 5. 测试验证 ──→ 6. 迭代优化            │
│       │                              │                  │
│       ↓                              ↓                  │
│  7. 文档编写 ──→ 8. 打包发布 ──→ 9. 维护更新            │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 3.2 阶段一：规划

在开始开发前，需要明确以下问题：

```markdown
## 规划清单

### 目标定义
- [ ] 资源包的主题和风格是什么？
- [ ] 要替换哪些资源（纹理/模型/声音）？
- [ ] 目标 Minecraft 版本是什么？
- [ ] 是否需要兼容 Mod？

### 技术评估
- [ ] 需要哪些自定义模型？
- [ ] 是否需要动画纹理？
- [ ] 是否需要修改着色器？
- [ ] 预计文件大小是多少？

### 时间规划
- [ ] 纹理制作预计时间
- [ ] 模型制作预计时间
- [ ] 测试和优化预计时间
```

### 3.3 阶段二：创建目录结构

```bash
# 创建基础目录结构
mkdir -p my-resourcepack/assets/minecraft/textures/block
mkdir -p my-resourcepack/assets/minecraft/textures/item
mkdir -p my-resourcepack/assets/minecraft/textures/entity
mkdir -p my-resourcepack/assets/minecraft/textures/gui
mkdir -p my-resourcepack/assets/minecraft/models/block
mkdir -p my-resourcepack/assets/minecraft/models/item
mkdir -p my-resourcepack/assets/minecraft/blockstates
mkdir -p my-resourcepack/assets/minecraft/sounds
mkdir -p my-resourcepack/assets/minecraft/lang
mkdir -p my-resourcepack/assets/minecraft/font
mkdir -p my-resourcepack/assets/minecraft/particles
```

### 3.4 阶段三：配置 pack.mcmeta

`pack.mcmeta` 是资源包的核心配置文件：

```json
{
  "pack": {
    "pack_format": 34,
    "description": [
      {
        "text": "我的资源包",
        "color": "gold",
        "bold": true
      },
      {
        "text": "\n版本 1.0.0",
        "color": "gray"
      },
      {
        "text": "\n全面美化，极致体验",
        "color": "aqua"
      }
    ],
    "supported_formats": [34, 35, 36]
  }
}
```

**pack_format 版本对照表**：

| Minecraft 版本 | pack_format |
|---------------|-------------|
| 1.20.3 - 1.20.4 | 22 |
| 1.20.5 - 1.20.6 | 32 |
| 1.21 - 1.21.1 | 34 |
| 1.21.2 - 1.21.3 | 42 |
| 1.21.4 | 46 |

### 3.5 阶段四：添加资源文件

根据开发计划，逐步添加各类资源文件：

```json
// 示例：添加自定义石头纹理
// 文件路径：assets/minecraft/textures/block/stone.png
// 尺寸：16x16 像素（标准方块纹理尺寸）

// 示例：添加自定义模型
// 文件路径：assets/minecraft/models/block/stone.json
{
  "parent": "minecraft:block/cube_all",
  "textures": {
    "all": "minecraft:block/stone"
  }
}
```

### 3.6 阶段五：测试验证

测试是资源包开发中至关重要的环节：

```
测试清单：
1. 功能测试
   - [ ] 所有替换的纹理是否正确显示
   - [ ] 自定义模型是否正确渲染
   - [ ] 声音是否正常播放
   - [ ] 动画是否流畅运行

2. 兼容性测试
   - [ ] 不同 Minecraft 版本测试
   - [ ] 不同显卡/驱动测试
   - [ ] 与其他资源包叠加测试
   - [ ] 与 Mod 的兼容性测试

3. 性能测试
   - [ ] FPS 是否有明显下降
   - [ ] 内存占用是否合理
   - [ ] 加载时间是否可接受

4. 视觉测试
   - [ ] 纹理风格是否统一
   - [ ] 颜色搭配是否协调
   - [ ] 细节是否清晰可见
```

**快速测试技巧**：

```bash
# 在游戏中按 F3 + T 重新加载资源包
# 无需退出游戏即可查看修改效果

# 使用命令检查资源加载
# /reload  - 重新加载数据包
# F3 + T   - 重新加载资源包
```

### 3.7 阶段六：打包发布

```bash

cd my-resourcepack
zip -r ../my-resourcepack-v1.0.0.zip .

# 确保 ZIP 文件结构正确
# my-resourcepack-v1.0.0.zip
# ├── pack.mcmeta
# ├── pack.png
# └── assets/
#     └── minecraft/
#         └── ...
```

## 四、常见开发场景

### 4.1 场景一：纹理替换

**适用场景**：替换游戏中的方块、物品、实体等纹理

```json
// 基本步骤：
// 1. 确定要替换的纹理路径
// 2. 创建相同尺寸的 PNG 图片
// 3. 放置到对应的目录位置

// 示例：替换钻石剑纹理
// 文件路径：assets/minecraft/textures/item/diamond_sword.png
// 尺寸：16x16 像素
```

**高级技巧 - 动画纹理**：

```json
// 纹理动画配置文件
// 文件路径：assets/minecraft/textures/block/stone.png.mcmeta
{
  "animation": {
    "frametime": 2,
    "frames": [
      {"index": 0, "time": 3},
      {"index": 1, "time": 1},
      {"index": 2, "time": 2},
      3,
      4,
      5
    ],
    "interpolate": true
  }
}
```

### 4.2 场景二：自定义模型

**适用场景**：创建独特的方块或物品模型

```json

// 文件路径：assets/minecraft/models/block/crafting_table.json

  "parent": "minecraft:block/cube_bottom_top",
  "textures": {
    "top": "minecraft:block/crafting_table_top",
    "side": "minecraft:block/crafting_table_side",
    "front": "minecraft:block/crafting_table_front"
  }
}

// 自定义物品模型（带自定义几何体）
{
  "parent": "minecraft:item/generated",
  "textures": {
    "layer0": "minecraft:item/diamond_sword"
  },
  "display": {
    "thirdperson_righthand": {
      "rotation": [0, -90, 55],
      "translation": [0, 4.0, 0.5],
      "scale": [0.85, 0.85, 0.85]

      "rotation": [0, -90, 25],
      "translation": [1.13, 3.2, 1.13],
```

### 4.10 场景十：性能优化

**适用场景**：优化资源包性能

```
优化策略：
1. 纹理优化
   - 使用合适的纹理尺寸（不要过度使用高分辨率）
   - 压缩 PNG 文件（使用 PNGQuant 或 TinyPNG）
   - 合并小纹理为纹理图集

2. 模型优化
   - 减少不必要的多边形
   - 使用纹理变量复用纹理
   - 避免过度复杂的元素嵌套

3. 声音优化
   - 使用适当的采样率（44100Hz 或 22050Hz）
   - 合理使用流式加载（stream: true）
   - 压缩音频文件

4. 加载优化
   - 使用 supported_formats 限制版本范围
   - 避免不必要的文件
   - 合理组织目录结构
```

## 五、推荐学习路径

```

├── 安装必要工具

└── 创建第一个资源包

├── 学习 PNG 格式基础
├── 替换简单方块纹理

├── 替换物品纹理
├── 学习基础模型语法
└── 使用 Blockbench 创建简单模型

第 6-7 天：综合练习
├── 创建主题资源包
├── 替换多种类型资源
└── 测试和优化
```

```
第 1 周：高级模型和动画

├── GLSL 基础语法

第 4 周：Mod 兼容和发布
```

## 七、常见问题解答

### Q1：资源包不生效怎么办？

```
排查步骤：
1. 检查 pack.mcmeta 是否正确
2. 检查目录结构是否正确
3. 检查文件名是否正确（区分大小写）
4. 检查 JSON 语法是否正确
5. 按 F3 + T 重新加载资源包
6. 检查游戏版本与 pack_format 是否匹配
```

### Q2：如何调试资源包？

```
调试技巧：
1. 使用 F3 调试屏幕查看资源加载信息
2. 检查游戏日志中的错误信息
3. 逐步添加资源，定位问题文件
4. 使用 JSON 验证工具检查语法
5. 对比原版资源文件
```

### Q3：资源包大小如何优化？

```
优化建议：
1. 使用 PNGQuant 压缩 PNG 文件
2. 使用 Audacity 压缩音频文件
3. 避免使用过高的纹理分辨率
4. 删除未使用的资源文件
5. 使用纹理图集减少文件数量
```
