# 声音包开发指南

## 一、Minecraft 声音系统概述

### 1.1 声音引擎架构

Minecraft 使用基于 OpenAL（Open Audio Library）的自定义声音引擎，负责管理游戏内所有声音事件的播放、混合和空间定位。声音引擎的核心组件包括：

- **声音事件（Sound Event）**：游戏中各种行为触发的声音抽象标识，如 `block.wood.place`、`entity.player.hurt` 等。每个事件可以在 `sounds.json` 中关联一个或多个声音文件。
- **声音池（Sound Pool）**：当一个声音事件关联多个声音文件时，游戏会从池中随机选择文件进行播放，从而实现音调的自然变化，避免重复感。
- **音频混合器（Audio Mixer）**：管理主音量、音乐、环境、天气、敌对生物、友好生物、玩家、方块、语音等独立音轨的混音和音量控制。
- **空间音频（Spatial Audio）**：基于声源与玩家视角的相对位置，计算立体声定位、距离衰减和音量变化，营造沉浸式听觉体验。

### 1.2 声音文件的格式要求

Minecraft 资源包支持的声音文件格式为 **OGG Vorbis**（`.ogg`），这是一种开源、高压缩比的有损音频格式，特别适合游戏场景。

- **采样率**：推荐 44100 Hz（CD 质量）或 48000 Hz。低于 22050 Hz 会导致明显的声音质量损失。
- **位深度**：OGG Vorbis 使用可变位率（VBR），推荐质量设置为 0.4~0.6（对应约 128~192 kbps），可在文件大小和质量之间取得良好平衡。
- **通道数**：
  - 大多数游戏内音效（方块放置、脚步声、实体声音）应使用 **单声道（Mono）**，便于游戏引擎进行空间定位处理。
  - 音乐音轨应使用 **立体声（Stereo）**，以保留原有的空间感和音场效果。
- **时长**：除音乐和流式声音外，一般声音文件建议控制在 0.5~5 秒内，过长的文件会增加内存占用。

### 1.3 声音文件的目录结构

声音文件放置在资源包的 `assets/<命名空间>/sounds/` 目录下，按照类别进行子目录划分：

```
assets/minecraft/sounds/
├── ambient/          # 环境音效（洞穴、水下、Nether）
│   ├── cave/
│   ├── nether/
│   └── underwater/
├── block/            # 方块音效（放置、破坏、步行走、挖掘）
│   ├── stone/
│   ├── wood/
│   ├── grass/
│   └── ...
├── entity/           # 实体音效（怪物、动物、玩家）
│   ├── player/
│   ├── creeper/
│   ├── zombie/
│   └── ...
├── music/            # 背景音乐
│   ├── game/
│   └── menu/
├── particle/         # 粒子效果音效
├── records/          # 唱片音乐
├── ui/               # UI 界面音效（按钮点击、物品栏打开）
└── weather/          # 天气音效（雷声、雨声）
```

## 二、sounds.json 格式详解

### 2.1 文件结构与位置

`sounds.json` 是声音包的核心配置文件，定义了声音事件与声音文件的映射关系。它位于资源包的 `assets/<命名空间>/sounds.json` 路径下。

```json
{
  "entity.creeper.primed": {
    "sounds": [
      "random/fuse"
    ],
    "subtitle": "subtitles.entity.creeper.primed"
  },
  "block.stone.break": {
    "sounds": [
      {
        "name": "block/stone/break1",
        "volume": 1.0,
        "pitch": 1.0,
        "weight": 1,
        "type": "event"
      },
      {
        "name": "block/stone/break2",
        "volume": 1.0,
        "pitch": 0.9,
        "weight": 2
      }
    ],
    "subtitle": "subtitles.block.stone.break"
  }
}
```

### 2.2 声音条目选项详解

每个声音文件条目（sounds 数组中的对象）可以配置以下属性：

#### 2.2.1 `name`（必需）

声音文件的路径。相对于 `sounds/` 目录，**不包含文件扩展名**。例如 `"block/stone/break1"` 对应 `sounds/block/stone/break1.ogg`。

#### 2.2.2 `volume`（可选，默认 1.0）

音量倍率，范围为 0.0~1.0。游戏的系统音量设置会在此基础上做最终调整。多个声音文件的音量可以在 `sounds.json` 中分别设置以实现不同的响度变化。

```
"volume": 0.8   # 以 80% 的音量播放
```

#### 2.2.3 `pitch`（可选，默认 1.0）

音调倍率，范围通常为 0.5~2.0。值为 1.0 表示原始音高，2.0 表示高一个八度，0.5 表示低一个八度。游戏内许多声音事件（如脚步声、破坏声）会以不同的音调播放同一声音文件，以增加变化。

```
"pitch": 1.2   # 提高 20% 的音调
```

**技巧**：如果要让游戏在 0.8~1.2 之间随机选择音调，不需要在 `sounds.json` 中配置随机范围，而是由游戏引擎自动为某些事件生成随机音调。如果希望所有变体使用固定音调，则在每个文件条目中显式指定 pitch 值。

#### 2.2.4 `weight`（可选，默认 1）

权重值，控制该声音文件在随机池中被选中的概率。权重越高，被选中的概率越大。

```json
"sounds": [
  { "name": "common", "weight": 10 },   // 较大概率选中
  { "name": "rare", "weight": 1 }        // 较小概率选中
]
```

当游戏触发声音事件时，会根据权重随机选择一个文件播放。上例中 `common` 被选中的概率是 `10/11`，`rare` 是 `1/11`。

#### 2.2.5 `type`（可选）

指定声音文件的类型。可选值：

- `"file"`（默认）：普通的 OGG 声音文件。
- `"event"`：引用另一个声音事件（`minecraft` 命名空间中的已有事件），可以实现声音事件的链式复用。

```json
{
  "sounds": [
    { "name": "minecraft:block.stone.break", "type": "event" }
  ]
}
```

#### 2.2.6 `stream`（可选，默认 false）

是否启用流式播放。当设置为 `true` 时，声音文件将以流的形式从磁盘读取，而不是一次性加载到内存中。这对长音频文件（如音乐、环境循环音效）非常重要，可以显著降低内存占用。

```json
{
  "name": "music/game/creative",
  "stream": true
}
```

**注意事项**：
- 流式播放会增加磁盘 I/O，不适合频繁触发的短音效。
- 背景音乐和较长的环境音效应启用 `stream: true`。
- 短音效（方块放置、实体受伤）不应启用流式播放。

#### 2.2.7 `attenuation_distance`（可选，默认 16）

声音的衰减距离，单位为方块。超出此距离后玩家将完全听不到该声音。此值影响到声音的空间定位效果。

```json
{
  "name": "block/anvil/land",
  "attenuation_distance": 32
}
```

- 一般方块声音：16 方块
- 爆炸、雷声等远处可闻的声音：可设置 48 或更高
- TNT 爆炸：64 方块

#### 2.2.8 `preload`（可选，默认 false）

是否在游戏启动时预加载此声音文件。对于高频使用的声音（如 UI 音效、脚步声），预加载可以减少首次播放时的延迟。但对于不常使用的声音，预加载会增加不必要的内存占用。

### 2.3 顶层配置选项

#### 2.3.1 `replace`（布尔值）

当为 `true` 时，当前资源包的声音定义将**完全替换**原版声音事件的所有声音文件，而不是追加。此选项适用于需要彻底改变某个声音效果的情况。

```json
{
  "entity.creeper.primed": {
    "sounds": [
      "custom/creeper_fuse"
    ],
    "replace": true,
    "subtitle": "subtitles.entity.creeper.primed"
  }
}
```

#### 2.3.2 `category`（字符串，已废弃）

在旧版本中用于指定声音分类（`"master"`、`"music"`、`"record"`、`"weather"`、`"block"`、`"hostile"`、`"neutral"`、`"player"`、`"ambient"`、`"voice"`）。该字段在较新版本中已被游戏客户端自动推断取代，但为了向后兼容，旧版资源包可能仍需指定。

#### 2.3.3 `subtitle`（字符串）

声音事件的字幕文本键。在语言文件中为对应键提供翻译后，当声音事件触发时，开启字幕的玩家会看到对应的文字描述。

```json
"subtitle": "subtitles.entity.creeper.primed"
```

对应的语言文件条目：
```json
"subtitles.entity.creeper.primed": "苦力怕：嘶~"
```

## 三、各类声音开发

### 3.1 环境音效（Ambient）

环境音效营造游戏世界的声音氛围，包括洞穴滴水、风吹树叶、地下岩浆冒泡等。

**洞穴环境音效**定义于 `minecraft` 命名空间的 `ambient.cave` 事件。原版使用了额外的随机算法在多首环境音轨间切换，包括 `cave1.ogg` 至 `cave19.ogg` 等多个文件。

**自定义环境音效**的创建步骤：

1. 在 `assets/<命名空间>/sounds/ambient/` 目录下创建子目录（如 `custom/`）。
2. 准备符合规格的 OGG 文件（建议使用流式播放）。
3. 在 `sounds.json` 中注册：

```json
{
  "ambient.cave": {
    "sounds": [
      { "name": "ambient/cave/cave1", "stream": true },
      { "name": "ambient/cave/cave2", "stream": true },
      { "name": "ambient/custom/my_ambient", "stream": true }
    ]
  }
}
```

**生物群系专属环境音效**可以通过自定义数据包（Data Pack）或模组实现，在 `sounds.json` 中定义事件后，通过数据包中的群系配置播放。

### 3.2 实体音效（Entity）

实体音效覆盖了所有生物和玩家的动作声音，包括：

- **受伤音效（`hurt`）**：被攻击时播放，通常有 3~5 个变体。
- **死亡音效（`death`）**：实体死亡时播放。
- **空闲音效（`ambient`）**：实体在空闲状态下随机播放（如鸡的咯咯叫、僵尸的低吼）。
- **步行走音效（`step`）**：实体行走时的脚步声，与下方块类型相关。
- **攻击音效（`attack`）**：实体攻击时播放。
- **特殊动作音效**：如苦力怕的嘶声、骷髅的射箭声、末影人的传送声。

**示例：添加自定义实体音效**

```json
{
  "entity.wolf.bark": {
    "sounds": [
      { "name": "entity/wolf/bark1", "weight": 5 },
      { "name": "entity/wolf/bark2", "weight": 3 }
    ],
    "subtitle": "subtitles.entity.wolf.bark"
  }
}
```

**玩家音效**相对固定，包括：

- `entity.player.hurt`：受伤音效（男版/女版随机切换，实际为不同音高）
- `entity.player.death`：死亡音效
- `entity.player.swim`：游泳音效
- `entity.player.splash`：溅水音效
- `entity.player.levelup`：升级音效

### 3.3 方块音效（Block）

方块音效是最复杂的声音类别之一，因为每个方块类型都有自己的一组音效。每个方块的声音由其**声音类型（Sound Type）**决定，不同方块可能共享同一声音类型（如石质类方块共享 `stone` 声音组）。

方块音效组通常包含以下事件：

- `block.<type>.place`：方块放置
- `block.<type>.break`：方块破坏
- `block.<type>.hit`：方块挖掘中
- `block.<type>.fall`：实体落在方块上
- `block.<type>.step`：在方块上行走

**修改方块音效**的步骤：

1. 在 `sounds.json` 中定位到目标方块声音事件。
2. 替换或添加声音文件引用。
3. 确保文件路径正确。

```json
{
  "block.grass.break": {
    "sounds": [
      { "name": "custom/grass/break1", "weight": 3 },
      { "name": "custom/grass/break2", "weight": 3 },
      { "name": "custom/grass/break3", "weight": 2 }
    ],
    "subtitle": "subtitles.block.grass.break"
  }
}
```

**注意**：方块的 hit/step/fall/place/break 事件分别独立，需要各自修改。如果只改了 `break` 而忽略 `step`，玩家在该方块上行走时仍会听到原版音效。

### 3.4 物品音效（Item）

物品音效相对简单，主要包括：

- **物品掉落（`entity.item.pickup`）**：拾取物品时播放。
- **物品栏移动（`entity.item.pickup`）**：实际与掉落拾取共享声音事件。
- **装备穿戴（`item.armor.equip_<type>`）**：穿戴盔甲时播放。
- **工具使用**：如打火石点火、钓鱼竿抛线等。
- **食物食用（`entity.player.burp`）**：进食完成时的打嗝声。
- **工具耐久消耗**：如盾牌格挡、弓拉弦的声音。

### 3.5 UI 音效（UI）

UI 音效包括：

- `ui.button.click`：按钮点击
- `ui.loom.select_pattern`：织布机图案选择
- `ui.stonecutter.take_result`：切石机取出物品
- `ui.toast.challenge_complete`：挑战成就完成

UI 音效通常使用短促的声音文件，无需流式播放，建议使用较高的音质设置以保证清晰度。

## 四、声音制作工具

### 4.1 Audacity

Audacity 是声音包开发的核心工具，免费开源，支持 Windows、macOS 和 Linux 平台。

**下载与安装**：
- 官方网站：https://www.audacityteam.org/
- 为导出 OGG 格式，需要额外安装 FFmpeg 库（在 Audacity 中通过"编辑"→"首选项"→"库"配置）。

**基本工作流程**：

1. **录制或获取源音频**：可以使用免费音效网站（如 Freesound、OpenGameArt）获取免版税音效，或录制自定义音频。

2. **导入音频**：在 Audacity 中选择"文件"→"导入"→"音频"（或直接拖入）。

3. **编辑与修剪**：
   - 使用选择工具选中所需片段。
   - 使用"效果"→"淡入"/"淡出"消除爆音。
   - 使用"效果"→"均衡器"调整频率响应。
   - 使用"效果"→"压缩器"动态范围压缩，使音量保持一致。

4. **标准化音量**：
   - 选择"效果"→"音量与压限"→"标准化（标准化至 -1.0 dB）"。
   - 确保所有声音文件的响度水平相对一致，避免某些声音过响或过轻。

5. **降噪处理**：
   - 选中一段纯噪音区域。
   - 选择"效果"→"降噪/修复"→"降噪"→"获取噪声样本"。
   - 全选音频后再次进入降噪效果，点击"确定"应用。

6. **导出为 OGG**：
   - 选择"文件"→"导出"→"导出音频"。
   - 格式选择"Ogg Vorbis"。
   - 质量滑块调整到 5~6（对应约 160~192 kbps）。

### 4.2 其他声音工具

- **FFmpeg**：命令行音频/视频处理工具，可用于批量格式转换，非常适合将大量 WAV 转换为 OGG。
  ```
  ffmpeg -i input.wav -c:a libvorbis -q:a 5 output.ogg
  ```

- **SoX（Sound eXchange）**：命令行音频处理工具，支持批量编辑和效果处理。

- **Adobe Audition**：专业级音频编辑软件，提供更高级的降噪、混音和修复功能（商业软件）。

- **Bfxr/Sfxr**：专门用于生成 8-bit/芯片音乐风格音效的工具，适合制作复古风格资源包。

## 五、声音优化策略

### 5.1 文件格式优化

- **选择合适位率**：对于大多数游戏音效，OGG Vorbis 质量 4~5（128~160 kbps）已足够。实验表明，超过 192 kbps 的音质提升人耳难以感知，但文件大小显著增加。
- **使用单声道**：非音乐音效应使用单声道，文件大小约为立体声的一半。
- **修剪空白**：删除音频首尾的不必要静音段，减少文件大小并降低播放延迟。

### 5.2 流式播放策略

合理配置 `stream` 属性可以在内存和磁盘 I/O 间取得平衡：

| 声音类型 | 是否流式 | 原因 |
|---------|---------|------|
| 音乐 (music/) | 是 | 文件大、时较长、不频繁触发 |
| 环境音效 (ambient/) | 是 | 循环播放、时较长 |
| 方块音效 (block/) | 否 | 频繁触发、文件短小 |
| 实体音效 (entity/) | 否 | 频繁触发、文件短小 |
| UI 音效 (ui/) | 否 | 文件极短、需要即时应答 |
| 唱片 (records/) | 是 | 音乐文件、时较长 |

### 5.3 文件数量优化

- 每个事件的声音变体数控制在 3~5 个即可，过多的变体会增加资源包体积和加载时间。
- 对于脚步声等高频事件，2~4 个变体通常足够。
- 合理使用 weight 值：让更自然的音效获得更高的权重，而不常见的变体权重设低。

### 5.4 延迟优化

- 使用 `preload: true` 预加载关键 UI 音效，避免首次点击时的延迟。
- 保持采样率统一（推荐 44100 Hz），避免运行时采样率转换开销。
- 避免声音文件嵌套过多目录层级。

## 六、常见问题与解决方案

### 6.1 声音文件播放失败

**现象**：游戏内声音不播放，控制台输出警告。

**检查步骤**：
1. 确认文件路径与 `sounds.json` 中 `name` 字段匹配（不包括扩展名和目录前缀）。
2. 确认文件格式为 OGG Vorbis，而非其他格式（即使扩展名为 `.ogg`）。
3. 检查文件命名是否包含非法字符，建议仅使用小写字母、数字和下划线。
4. 确认 JSON 格式正确（使用 JSON 验证工具检查）。

### 6.2 声音播放有杂音或爆音

**现象**：声音播放时出现嘶嘶声、咔嚓声或爆裂声。

**原因与解决**：
- **音量过高**：在 Audacity 中标准化至 -1 dB 以下。
- **剪辑不齐**：确保音频片段在零点交叉处剪裁，或应用 10ms 淡入淡出。
- **采样率失配**：确保所有文件使用相同采样率（44100 Hz）。
- **编码质量问题**：尝试提高 OGG 质量设置。

### 6.3 声音位置定位错误

**现象**：声音似乎来自错误的方向或距离。

**原因与解决**：
- 声音文件为立体声时，游戏的空间定位算法可能异常。将文件转换为单声道。
- `attenuation_distance` 设置过短，导致声音提前静音。
- 检查是否有多个同名声音事件冲突。

### 6.4 资源包加载后声音缺失

**现象**：安装资源包后，某些原版声音消失。

**原因与解决**：
- 意外使用了 `replace: true` 导致原版声音被完全替换。如果没有在 `sounds` 数组中包含所有原版条目，某些声音就会丢失。
- 解决方案：移除 `replace` 字段或确保 `sounds` 数组包含所有必要的声音文件。

### 6.5 JSON 解析错误

**现象**：游戏启动时显示 JSON 解析错误。

**常见问题**：
- 尾随逗号（JSON 标准不允许最后一个元素后跟逗号）。
- 注释（JSON 标准不支持 `//` 或 `/* */` 注释）。
- 字符串缺少引号。
- 括号不匹配。

**建议**：使用 Visual Studio Code、IntelliJ IDEA 等 IDE 编辑 JSON 文件，它们会自动提示语法错误。

### 6.6 声音文件过大导致内存占用高

**现象**：游戏占用大量内存，加载资源包时卡顿。

**解决方案**：
- 对长音频启用 `stream: true`。
- 降低 OGG 编码质量（从 6 降至 4）。
- 缩短音频时长，删除不必要的部分。
- 使用单声道替代立体声。

### 6.7 自定义声音事件不工作

如果声音事件是自定义的（非原版事件），需要确保：
1. 对应的声音事件在游戏代码或数据包中已注册。
2. 使用 `type: "event"` 引用的已有事件确实存在。
3. 命名空间使用正确（默认为 `minecraft`，自定义命名空间需要模组或数据包支持）。

## 七、高级技巧

### 7.1 声音事件的动态组合

通过 `type: "event"` 可以将多个声音事件组合使用，创建复杂的声音效果：

```json
{
  "custom.rain_forest": {
    "sounds": [
      { "name": "minecraft:ambient.cave", "type": "event", "weight": 3 },
      { "name": "minecraft:weather.rain", "type": "event", "weight": 5 }
    ]
  }
}
```

### 7.2 季节/环境变化的音量控制

虽然没有直接的季节判断机制，但可以通过模组或数据包动态切换资源包，配合不同的 `sounds.json` 文件实现季节性的声音变化。

### 7.3 兼容性资源包配置

在与他人共享资源包时，建议在 `pack.mcmeta` 中注明所需的声音格式要求，并在 `sounds.json` 中使用 `replace` 标记明确覆盖行为，方便其他资源包制作者理解你的设计意图。

## 八、小结

声音包是 Minecraft 资源包中容易被忽视但极为重要的组成部分。精心制作的声音包可以从听觉维度大幅提升游戏的沉浸感和氛围。开发者需要掌握的主要技能包括：

1. 理解声音系统和 `sounds.json` 的完整配置。
2. 掌握 OGG 音频文件的制作、编辑和优化。
3. 熟悉各类声音事件（环境、实体、方块、UI）的配置方法。
4. 善用音效编辑工具进行音频处理和格式转换。
5. 合理配置流式播放、预加载和权重参数来优化性能。

通过本指南的学习和实践，你将能够创建出高质量、高性能的 Minecraft 声音资源包，为玩家带来更加丰富和沉浸式的游戏听觉体验。
