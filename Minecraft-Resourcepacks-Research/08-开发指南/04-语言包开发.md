## 1. Minecraft 本地化系统概述

### 1.1 语言文件机制

Minecraft 使用基于 JSON 的键值对（Key-Value）本地化系统。游戏中的所有文本——从方块名称到 GUI 提示——都通过**翻译键**（Translation Key）进行索引，而非硬编码字符串。

**工作流程**：

```
代码中使用翻译键 → 查询当前语言 → 加载对应 lang/*.json → 替换为本地化文本
```

例如，游戏中显示"钻石剑"的过程：

1. 代码中引用翻译键 `item.minecraft.diamond_sword`
2. 系统检测当前语言设置为 `zh_cn`
3. 从 `assets/minecraft/lang/zh_cn.json` 中查找该键
4. 返回值 `"钻石剑"` 并显示

**核心特性**：

- **非破坏性覆盖**：资源包可以只覆盖部分翻译键，未覆盖的键回退到原版
- **多包叠加**：多个资源包的翻译可按优先级合并
- **热重载**：切换语言时无需重启游戏（1.13+）

### 1.2 语言代码规范

Minecraft 使用 `xx_yy` 格式的语言代码，其中：

- `xx`：ISO 639-1 语言代码（小写），如 `zh`、`en`、`ja`
- `y`：ISO 3166-1 地区/变体代码（小写），如 `cn`、`tw`、`us`、`gb`

**常用语言代码**：

| 语言代码 | 语言名称 | 说明 |
|---------|---------|------|
| `en_us` | English (US) | 默认语言，回退基准 |
| `zh_cn` | 简体中文 | 中国大陆 |
| `zh_tw` | 繁體中文 | 台湾地区 |
| `ja_jp` | 日本語 | 日本 |
| `ko_kr` | 한국어 | 韩国 |
| `de_de` | Deutsch | 德语 |
| `fr_fr` | Français | 法语 |
| `es_es` | Español | 西班牙语 |
| `pt_br` | Português (Brasil) | 巴西葡萄牙语 |
| `ru_ru` | Русский | 俄语 |

**完整列表**：Minecraft 内置约 120+ 种语言代码，完整列表可在 `assets/minecraft/lang/languages.json` 中查看。

### 1.3 语言文件加载优先级

语言文件的加载遵循严格的优先级机制：

```
高优先级
  │
  ├─ 最后加载的资源包（列表顶部）
  │    └─ assets/<namespace>/lang/<lang_code>.json
  │
  ├─ 更早加载的资源包
  │    └─ assets/<namespace>/lang/<lang_code>.json
  │
  ├─ 原版资源包（Minecraft 内置）
  │    └─ assets/minecraft/lang/<lang_code>.json
  │
  └─ 回退到 en_us（若目标语言缺少翻译）
低优先级
```

**关键规则**：

1. **同名覆盖**：若资源包 A 和 B 都定义了键 `X`，优先级更高的包的值生效
2. **增量合并**：资源包只需定义要覆盖的键，其余键从低优先级包继承
3. **命名空间隔离**：不同命名空间的翻译键互不干扰
4. **en_us 回退**：任何语言缺少的翻译键都会回退到 `en_us` 的值

**优先级示例**：

```
资源包列表（从上到下加载）：
├─ 1. 我的语言包（最高优先级）
├─ 2. 某 Mod 资源包
└─ 3. 原版 Minecraft（最低优先级）

加载结果：
- 我的语言包定义的键 → 使用我的翻译
- 我的语言包未定义但 Mod 定义的键 → 使用 Mod 翻译
- 两者都未定义的键 → 使用原版翻译
- 原版也未定义 → 显示翻译键本身
```

## 2. 语言文件格式

### 2.1 文件路径

语言文件必须遵循以下路径结构：

```
<资源包根目录>/
└── assets/
    └── <namespace>/
        └── lang/
            ├── en_us.json      ← 英语（推荐始终包含）
            ├── zh_cn.json      ← 简体中文
            ├── zh_tw.json      ← 繁体中文
            ├── ja_jp.json      ← 日语
            └── languages.json  ← 可选：注册自定义语言
```

- **原版命名空间**：`minecraft`（覆盖原版翻译时使用）
- **Mod 命名空间**：通常为 Mod ID，如 `create`、`ae2`
- **自定义命名空间**：资源包作者自定义的标识符

### 2.2 JSON 格式：键值对结构

语言文件是一个扁平的 JSON 对象，每个键值对代表一条翻译：

```json
{
  "block.minecraft.stone": "石头",
  "block.minecraft.dirt": "泥土",
  "block.minecraft.grass_block": "草方块",
  "item.minecraft.diamond_sword": "钻石剑",
  "entity.minecraft.zombie": "僵尸"
}
```

**格式要求**：

- 文件编码：**UTF-8**（必须，否则中文等字符会乱码）
- 行尾符号：LF 或 CRLF 均可
- 缩进：无硬性要求，推荐 2 空格或 4 空格
- 尾逗号：**不允许**（严格 JSON 格式）

### 2.3 键名命名规范

翻译键采用**点分层次命名**，遵循以下约定：

```
<类型>.<命名空间>.<标识符>
```

**命名规则**：

- 使用**小写字母**和**下划线**（snake_case）
- 点号 `.` 作为层级分隔符
- 命名空间通常为 `minecraft`（原版）或 Mod ID
- 标识符使用下划线分隔的英文单词

**常见键名模式**：

| 类型 | 键名模式 | 示例 |
|------|---------|------|
| 方块 | `block.<ns>.<id>` | `block.minecraft.oak_log` |
| 物品 | `item.<ns>.<id>` | `item.minecraft.bread` |
| 实体 | `entity.<ns>.<id>` | `entity.minecraft.creeper` |
| 附魔 | `enchantment.<ns>.<id>` | `enchantment.minecraft.sharpness` |
| 药水效果 | `effect.<ns>.<id>` | `effect.minecraft.speed` |
| GUI | `gui.<ns>.<key>` | `gui.minecraft.done` |
| 死亡消息 | `death.attack.<key>` | `death.attack.player` |
| 进度 | `advancements.<ns>.<key>.title` | `advancements.minecraft.story.root.title` |
| 选项 | `options.<key>` | `options.music` |
| 命令 | `commands.<key>` | `commands.give.success` |

### 2.4 格式化占位符

语言文件支持 Java `String.format` 风格的占位符，用于动态插入变量。

**基本占位符**：

| 占位符 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| `%s` | 字符串 | 按顺序插入 | `"给 %s 一个 %s"` |
| `%d` | 整数 | 按顺序插入 | `"已有 %d 个玩家"` |
| `%f` | 浮点数 | 按顺序插入 | `"坐标：%.1f"` |
| `%%` | 转义 | 显示字面量 `%` | `"完成 100%%"` |

**带位置索引的占位符**：

不同语言的语序可能不同，使用位置索引 `%n$s` 可以调整参数顺序：

```json
{
  "commands.give.success.single": "已将 %s 给予 %s",
  "commands.give.success.single.reordered": "已将 %2$s 给予 %1$s"
}
```

- `%1$s`：第一个字符串参数
- `%2$s`：第二个字符串参数
- `%1$d`：第一个整数参数

**实际应用示例**：

```json
{
  "multiplayer.player.joined": "%s 加入了游戏",
  "multiplayer.player.left": "%s 离开了游戏",
  "death.attack.player": "%1$s 被 %2$s 杀死了",
  "death.attack.mob": "%1$s 被 %2$s 杀死了",
  "commands.give.success.single": "已将 [%s] * %d 给予 %s",
  "enchantment.level.1": "I",
  "enchantment.level.2": "II"
}
```

> **注意**：占位符的顺序在不同语言中必须与原文一致，除非使用位置索引。翻译时需特别注意参数对应关系。

### 2.5 格式化代码（Section Sign）

Minecraft 使用 `§`（Section Sign，U+00A7）字符实现文本格式化。格式化代码由 `§` 后跟一个十六进制字符组成。

**颜色代码**：

| 代码 | 颜色 | 十六进制 RGB | 说明 |
|------|------|-------------|------|
| `§0` | 黑色 | `#000000` | |
| `§1` | 深蓝色 | `#0000AA` | |
| `§2` | 深绿色 | `#00AA00` | |
| `§3` | 青色 | `#00AAAA` | |
| `§4` | 深红色 | `#AA0000` | |
| `§5` | 紫色 | `#AA00AA` | |
| `§6` | 金色 | `#FFAA00` | 常用于标题 |
| `§7` | 灰色 | `#AAAAAA` | |
| `§8` | 深灰色 | `#555555` | |
| `§9` | 蓝色 | `#5555FF` | |
| `§a` | 绿色 | `#55FF55` | |
| `§b` | 天蓝色 | `#55FFFF` | |
| `§c` | 红色 | `#FF5555` | 常用于错误/警告 |
| `§d` | 粉红色 | `#FF55FF` | |
| `§e` | 黄色 | `#FFFF55` | 常用于提示 |
| `§f` | 白色 | `#FFFFFF` | |

**格式代码**：

| 代码 | 效果 | 说明 |
|------|------|------|
| `§l` | **粗体** | Bold |
| `§m` | ~~删除线~~ | Strikethrough |
| `§n` | <u>下划线</u> | Underline |
| `§o` | *斜体* | Italic |
| `§k` | 混淆文本 | Obfuscated（随机闪烁字符） |
| `§r` | 重置 | 重置所有格式到默认 |

**使用示例**：

```json
{
  "custom.title": "§6§l重要公告§r",
  "custom.warning": "§c注意：此操作不可撤销！§r",
  "custom.tip": "§a提示：§e按 E 键打开物品栏§r",
  "custom.secret": "§5§o这是一段神秘的文字...§r",
  "custom.mixed": "§6金§a绿§b蓝§c红§r"
}
```

**格式化叠加规则**：

- 颜色代码会覆盖之前的颜色
- 格式代码（粗体、斜体等）可以叠加
- `§r` 会重置所有格式
- 新的颜色代码不会清除粗体/斜体等格式（反之亦然）

```
§l§c  → 粗体 + 红色
§6    → 粗体 + 金色（保留了粗体）
§r    → 重置为默认
```
