# 动画资源包开发指南

## 一、Minecraft 动画系统概述

### 1.1 动画系统的三个层次

Minecraft 的动画系统可以分为三个独立但相互关联的层次：

1. **纹理动画（Texture Animation）**：通过 `.mcmeta` 文件定义纹理帧序列，使纹理方块表面产生动态变化。这是最基础、兼容性最好的动画方式，适用于所有版本。
2. **自定义实体模型动画（CEM - Custom Entity Models）**：通过 OptiFine 的 `.jem` 和 `.jpm` 文件定义实体的 3D 模型变形和骨骼动画，是最强大的实体动画系统。
3. **粒子动画（Particle Animation）**：通过粒子定义文件和纹理动画控制粒子的外观和行为变化。

### 1.2 动画系统的应用场景

| 动画类型 | 典型应用 | 技术依赖 |
|---------|---------|---------|
| 纹理动画 | 流动的熔岩/水、闪烁的红石矿石、旋转的附魔效果 | 原版 |
| 实体动画 | 自定义生物行走、攻击姿势、翅膀扇动 | OptiFine CEM |
| 粒子动画 | 自定义粒子效果、环境粒子行为 | 原版/OptiFine |
| GUI 动画 | 进度条动画、按钮悬停效果 | 原版 |

### 1.3 动画性能考量

动画是资源包中最消耗性能的部分之一，需要特别注意：

- **帧率控制**：过高帧率的动画会显著增加 GPU 负担。建议大多数方块纹理动画使用 8~20 FPS。
- **内存占用**：多帧纹理会增加显存占用。控制帧数在合理范围内（通常 4~16 帧）。
- **插值开销**：开启帧间插值（Interpolation）会增加计算量，仅在需要平滑过渡时启用。
- **CEM 复杂度**：复杂的实体骨骼动画会影响实体渲染性能，对大量实体同时出现时影响尤为明显。

## 二、纹理动画

### 2.1 动画文件格式

纹理动画通过 `.mcmeta` 文件控制，该文件与对应的纹理 PNG 文件放在同一目录，命名格式为 `<纹理文件名>.png.mcmeta`。

**目录示例**：

```
assets/minecraft/textures/block/
├── lava_still.png          # 静态熔岩纹理
├── lava_still.png.mcmeta   # 熔岩动画定义
├── lava_flow.png
├── lava_flow.png.mcmeta
├── fire_0.png
├── fire_0.png.mcmeta
└── ...
```

### 2.2 MCmeta 动画格式

`.mcmeta` 文件的 `animation` 部分定义了纹理的动画行为：

```json
{
  "animation": {
    "interpolate": false,
    "width": 16,
    "height": 128,
    "frametime": 2,
    "frames": [
      0,
      1,
      2,
      3,
      2,
      1,
      {
        "index": 4,
        "time": 6
      },
      5
    ]
  }
}
```

#### 2.2.1 `interpolate`（布尔值，可选，默认 false）

是否在帧之间进行颜色插值。启用后游戏会自动在相邻帧之间生成过渡帧，使动画更加平滑。

```json
"interpolate": true
```

**注意**：插值会增加计算开销，且可能导致某些像素在非整数位置采样，产生模糊效果。建议在：
- 需要平滑过渡时使用（如熔岩流动）。
- 帧率较低时使用（减少抽搐感）。
- 不推荐用于高对比度或像素艺术的纹理。

#### 2.2.2 `width` / `height`（整数，可选）

定义单帧的尺寸。纹理 PNG 文件可以包含多帧画面，按垂直方向排列。

- `width`：单帧的宽度（像素）。如果省略，则使用纹理的实际宽度。
- `height`：单帧的高度（像素）。如果省略，则使用纹理的实际宽度（即使用方形帧）。

**示例**：一个 16x64 像素的纹理，帧高为 16 像素，则有 4 帧。

```json
{
  "animation": {
    "width": 16,
    "height": 16,
    "frametime": 3
  }
}
```

**重要**：如果纹理尺寸不是正方形（如 16x64），且未指定 `height`，则游戏会将宽度作为帧高度，意味着 `height` 默认为 `width` 的值。纹理的总高度 ÷ 帧高度 = 帧数。

#### 2.2.3 `frametime`（整数，可选，默认 1）

每帧的显示时间，单位是**游戏刻**（1 秒 = 20 游戏刻）。默认值 1 表示每帧显示 1 刻（0.05 秒），即 20 FPS。

```json
"frametime": 2  // 每帧 2 刻 = 0.1 秒 = 10 FPS
```

**推荐值**：
- 熔岩/水：4（5 FPS）
- 火：2（10 FPS）
- 植物生长：6~10（2~3.3 FPS）
- 快速闪烁效果：1（20 FPS）

#### 2.2.4 `frames`（数组，可选）

定义帧的播放顺序和每帧的独立时长。如果省略此字段，则按纹理中从上到下的顺序依次播放所有帧。

```json
"frames": [
  0,        // 第0帧，时长使用 frametime
  1,        // 第1帧
  2,        // 第2帧
  {
    "index": 1,  // 再次播放第1帧
    "time": 10   // 持续 10 刻（0.5 秒）
  },
  0
]
```

**帧索引**：从 0 开始计数，0 为纹理最上方的帧。

**独立时长**：帧对象中的 `time` 字段覆盖全局 `frametime`，单位为游戏刻。

**技巧**：通过帧数组可以实现：
- **非循环播放**：虽然动画总是会循环，但可以通过合理安排帧顺序达到类似效果。
- **特殊的节奏**：如心跳效果（快-快-慢-停顿）。
- **子帧引用**：重复使用某些帧以节省纹理空间。

### 2.3 原版动画纹理分析

#### 2.3.1 熔岩动画

原版熔岩使用两个纹理文件：
- `lava_still.png`：静态熔岩表面动画（16x64，4 帧）
- `lava_flow.png`：流动熔岩动画（16x128，8 帧）

`lava_still.png.mcmeta`：
```json
{
  "animation": {
    "interpolate": true,
    "frametime": 4
  }
}
```

熔岩动画启用了插值以实现平滑的流动效果，帧率为 5 FPS（frametime=4）。

#### 2.3.2 火焰动画

火焰纹理使用垂直堆叠的多帧纹理：
- `fire_0.png`：16x64（4 帧）
- `fire_1.png`：16x64（4 帧）

`fire_0.png.mcmeta`：
```json
{
  "animation": {
    "frametime": 2
  }
}
```

火焰动画每帧持续 2 刻（10 FPS），未启用插值，保持了像素风格的清晰感。

#### 2.3.3 红石矿石闪烁

红石矿石通过 `redstone_ore.png.mcmeta` 实现闪烁效果：
```json
{
  "animation": {
    "frametime": 1,
    "frames": [0, 1, 0, 0, 1, 1]
  }
}
```

通过帧数组控制闪烁节奏，模拟红石能量的脉冲感。

### 2.4 自定义纹理动画制作

**步骤 1：准备帧纹理**：

在图像编辑软件中创建纹理的每一帧。将所有帧按垂直方向排列在一张 PNG 图片中。

例如：创建 16x64 像素的纹理（4 帧，每帧 16x16）。

**步骤 2：创建 `.mcmeta` 文件**：

在与纹理相同的目录中创建 `<纹理名>.png.mcmeta` 文件：

```json
{
  "animation": {
    "interpolate": false,
    "frametime": 3,
    "frames": [0, 1, 2, 1]
  }
}
```

**步骤 3：测试与调整**：

1. 将纹理放入资源包的对应目录。
2. 在游戏中放置对应方块，观察动画效果。
3. 根据效果调整帧顺序和帧时间。

### 2.5 纹理动画最佳实践

1. **帧数控制**：建议使用 4~8 帧。帧数过少动画不流畅，过多则浪费资源。
2. **帧时间选择**：根据动画内容选择合适的帧时间。快速动作用 1~2，慢速动作用 3~6。
3. **循环平滑**：确保最后一帧到第一帧的过渡自然，避免视觉跳跃。
4. **插值使用**：仅在需要平滑过渡时启用，像素风格动画禁用它。
5. **色彩一致性**：保持所有帧的色调和亮度一致，避免闪烁。
6. **文件大小**：多帧纹理的文件大小为帧数 × 单帧大小。合理控制总文件大小。

## 三、CEM 实体动画（OptiFine）

### 3.1 CEM 动画系统概述

OptiFine 的 Custom Entity Models（CEM）系统支持创建带有动画的自定义实体模型。动画在 `.jem`（Java Entity Model）和 `.jpm`（Java Particle Model）文件中定义。

CEM 动画的核心特点：

- **骨骼驱动**：模型由骨骼层次结构驱动，骨骼变换影响其子元素。
- **变量驱动**：动画基于游戏运行时变量（如肢体摆动角度、游戏时间、实体速度）。
- **脚本支持**：支持简单的数学表达式，实现复杂的动画逻辑。
- **覆盖原版**：可以完全替换原版实体模型和动画。

### 3.2 动画变量系统

CEM 动画支持多种运行时变量，可在动画表达式中使用：

#### 3.2.1 角度变量

| 变量名 | 类型 | 范围 | 说明 |
|-------|------|------|------|
| `headYaw` | float | -180~180 | 头部水平旋转角度（度） |
| `headPitch` | float | -90~90 | 头部垂直旋转角度（度） |
| `limbSwing` | float | 0~∞ | 肢体摆动幅度（行走/奔跑时变化） |
| `limbSwingSpeed` | float | 0~∞ | 肢体摆动速度（与移动速度相关） |
| `bodyYaw` | float | -180~180 | 身体水平旋转角度 |
| `prevHeadYaw` | float | | 上一帧的头部水平角度 |
| `prevHeadPitch` | float | | 上一帧的头部垂直角度 |

#### 3.2.2 时间变量

| 变量名 | 类型 | 说明 |
|-------|------|------|
| `ageInTicks` | float | 实体存在的刻数（从生成计时） |
| `ticksExisted` | float | 同上，ageInTicks 的别名 |
| `wingRotation` | float | 翅膀旋转角度（用于幻翼等飞行生物） |
| `wingPos` | float | 翅膀位置 |

#### 3.2.3 位置与状态变量

| 变量名 | 类型 | 说明 |
|-------|------|------|
| `posX`/`posY`/`posZ` | float | 实体的世界坐标 |
| `motionX`/`motionY`/`motionZ` | float | 实体的速度向量 |
| `isSneaking` | bool | 是否潜行 |
| `isSprinting` | bool | 是否疾跑 |
| `isInWater` | bool | 是否在水中 |
| `isOnGround` | bool | 是否在地面上 |
| `isChild` | bool | 是否为幼年形态 |
| `health` | float | 当前生命值 |
| `hurtTime` | float | 受伤闪烁剩余时间 |
| `maxHurtTime` | float | 受伤总时间 |
| `deathTime` | float | 死亡动画进度 |

#### 3.2.4 攻击变量

| 变量名 | 类型 | 说明 |
|-------|------|------|
| `attackTime` | float | 攻击动画进度（受击后变化） |
| `swingProgress` | float | 手臂挥动进度（0.0~1.0） |

### 3.3 动画表达式语法

CEM 动画使用基于数学表达式的语法来定义骨骼变换。支持以下操作：

**基本运算**：
- 加减乘除：`+`、`-`、`*`、`/`
- 取模：`%`
- 负号：`-`

**数学函数**：
- `sin(x)`、`cos(x)`、`tan(x)`：三角函数（参数为弧度）
- `abs(x)`：绝对值
- `floor(x)`、`ceil(x)`：向下/向上取整
- `min(a, b)`、`max(a, b)`：最小/最大值
- `clamp(x, min, max)`：限制范围
- `sqrt(x)`：平方根
- `pow(x, y)`：幂运算
- `mod(x, y)`：取模

**条件表达式**：
- `a ? b : c`：三元运算，a 为真时取 b，否则取 c
- `equals(a, b)`：比较 a 和 b 是否相等（浮点数近似比较）

### 3.4 JEM 文件中的动画定义

在 `.jem` 文件中，动画通过 `animations` 字段定义：

```json
{
  "geometry": {
    "model": "geometry.animal",
    "texture": "textures/entity/animal.png"
  },
  "animations": {
    "walk": {
      "leftLeg": {
        "rotation": [
          0,
          0,
          "sin(limbSwing * 0.6662) * 1.4"
        ]
      },
      "rightLeg": {
        "rotation": [
          0,
          0,
          "sin(limbSwing * 0.6662 + Math.PI) * 1.4"
        ]
      },
      "leftArm": {
        "rotation": [
          0,
          0,
          "sin(limbSwing * 0.6662 + Math.PI) * 1.4"
        ]
      },
      "rightArm": {
        "rotation": [
          0,
          0,
          "sin(limbSwing * 0.6662) * 1.4"
        ]
      }
    },
    "idle": {
      "head": {
        "rotation": [
          "headPitch * 0.0174533",
          "headYaw * 0.0174533",
          0
        ]
      }
    }
  },
  "animations_comment": "不同动画状态的切换条件",
  "animationStates": {
    "default": ["idle", "walk"],
    "walking": "walk",
    "idle": "idle"
  }
}
```

#### 3.4.1 动画关键帧

对于复杂的动画，可以使用关键帧（Keyframe）系统：

```json
{
  "walk": {
    "leftLeg": {
      "rotation": {
        "0": [0, 0, 0],
        "5": [0, 0, "-30"],
        "10": [0, 0, 0],
        "15": [0, 0, "30"],
        "20": [0, 0, 0]
      }
    }
  }
}
```

关键帧的键是时间（刻），值是对应的骨骼变换。

#### 3.4.2 动画状态切换

通过 `animationStates` 定义实体的不同动画状态以及切换条件：

```json
{
  "animationStates": {
    "default": "idle",
    "walking": {
      "animation": "walk",
      "blend": 0.2,
      "speed": "limbSwingSpeed"
    },
    "attacking": {
      "animation": "attack",
      "blend": 0.1
    }
  }
}
```

- `default`：默认状态。
- `blend`：混合时间（秒），用于动画间的平滑过渡。
- `speed`：动画播放速度。

### 3.5 骨骼变换类型

CEM 支持三种骨骼变换：

**位移（Translation）**：

```json
{
  "body": {
    "translation": [0, "sin(ageInTicks * 0.1) * 0.5", 0]
  }
}
```

**旋转（Rotation）**：

```json
{
  "head": {
    "rotation": ["headPitch", "headYaw", 0]
  }
}
```

**缩放（Scale）**：

```json
{
  "body": {
    "scale": [1, "1 + sin(ageInTicks * 0.05) * 0.05", 1]
  }
}
```

### 3.6 常见实体动画效果

#### 3.6.1 步行/奔跑动画

标准的四足生物行走动画：
- 前腿与对角后腿同步摆动。
- 摆动幅度随速度增加。

```json
{
  "frontLeftLeg": {
    "rotation": [0, 0, "sin(limbSwing * 0.6662) * 1.4"]
  },
  "frontRightLeg": {
    "rotation": [0, 0, "sin(limbSwing * 0.6662 + 3.1416) * 1.4"]
  },
  "backLeftLeg": {
    "rotation": [0, 0, "sin(limbSwing * 0.6662 + 3.1416) * 1.4"]
  },
  "backRightLeg": {
    "rotation": [0, 0, "sin(limbSwing * 0.6662) * 1.4"]
  }
}
```

#### 3.6.2 呼吸/空闲动画

通过 `ageInTicks` 实现持续的微动：

```json
{
  "body": {
    "translation": [0, "sin(ageInTicks * 0.1) * 0.05", 0]
  },
  "chest": {
    "scale": [1, "1 + sin(ageInTicks * 0.15) * 0.03", 1]
  }
}
```

#### 3.6.3 攻击动画

```json
{
  "attack": {
    "rightArm": {
      "rotation": {
        "0": [0, 0, 0],
        "2": ["-90", 0, 0],
        "4": [0, 0, 0]
      }
    }
  },
  "animationStates": {
    "attacking": {
      "animation": "attack",
      "blend": 0.05,
      "triggersOn": "attackTime > 0"
    }
  }
}
```

#### 3.6.4 飞行/漂浮动画

```json
{
  "fly": {
    "wings": {
      "rotation": [0, 0, "sin(ageInTicks * 0.5) * 30"]
    }
  }
}
```

## 四、粒子动画

### 4.1 粒子动画基础

粒子动画控制粒子的外观和行为，包括纹理变化、大小变化、颜色变化等。

**粒子纹理动画**：

粒子纹理（位于 `textures/particle/`）也可以使用 `.mcmeta` 定义动画：

```json
// textures/particle/effect.png.mcmeta
{
  "animation": {
    "frametime": 2,
    "frames": [0, 1, 2, 3, 2, 1]
  }
}
```

### 4.2 粒子行为配置

通过数据包中的粒子定义文件（`data/<命名空间>/particles/`），可以控制粒子的行为参数：

```json
{
  "textures": [
    "minecraft:particle/effect_0",
    "minecraft:particle/effect_1",
    "minecraft:particle/effect_2"
  ],
  "options": {
    "size": [0.2, 0.6],
    "lifetime": [20, 60],
    "speed": [0.0, 0.2]
  }
}
```

### 4.3 OptiFine 自定义粒子

OptiFine 支持通过 `.properties` 文件定义自定义粒子，可以指定纹理、动画、行为等。

## 五、动画开发工具

### 5.1 Blockbench

Blockbench 是 Minecraft 资源包开发的首选工具，尤其适合 CEM 动画开发。

**主要功能**：
- **模型编辑**：创建和编辑 `.jem` 兼容的实体模型。
- **动画编辑器**：可视化创建关键帧动画，支持时间轴和曲线编辑。
- **骨骼系统**：建立骨骼层级结构，控制骨骼变换。
- **纹理绘制**：直接在 3D 模型上绘制纹理。
- **导出**：支持导出为 `.jem`、`.json`（原版模型）等多种格式。

**动画编辑工作流程**：

1. 创建/导入实体模型。
2. 建立骨骼层级（头部、身体、四肢等）。
3. 在动画模式中添加关键帧：
   - 选择骨骼。
   - 在时间轴上定位到目标帧。
   - 调整旋转/位移/缩放。
   - 设置插值类型（线性、平滑、步进）。
4. 预览动画效果。
5. 导出为 `.jem` 格式。

**关键帧插值类型**：
- **Linear**：线性插值，匀速过渡。
- **Smooth**：缓入缓出，自然的加速减速。
- **Step**：步进，无过渡（适合像素风格）。

### 5.2 图像编辑软件

纹理动画的帧制作需要图像编辑软件：

- **Aseprite**：专业的像素艺术编辑工具，特别适合制作像素动画帧。
- **Photoshop**：支持时间轴和帧动画功能。
- **GIMP**：免费开源，支持帧动画编辑。
- **Krita**：免费的专业绘画软件，支持动画帧制作。

### 5.3 JSON 编辑器

`.mcmeta`、`.jem` 等配置文件需要使用文本编辑器：

- **Visual Studio Code**：支持 JSON 语法高亮和验证。
- **Notepad++**：轻量级编辑器，支持 JSON 格式化。
- **在线 JSON 验证器**：用于检查 JSON 语法正确性。

### 5.4 预览与测试工具

- **Minecraft 客户端**：最终测试环境。
- **OptiFine**：CEM 动画需要 OptiFine 支持。
- **CIT Resewn**：替代 OptiFine 的 CEM 兼容模组（Fabric 版）。

## 六、性能优化

### 6.1 纹理动画优化

- **减少帧数**：每个动画纹理的帧数控制在 4~16 帧。
- **降低帧率**：使用较低的 `frametime` 值（3~6）。
- **控制插值**：仅在必要时启用帧间插值。
- **纹理尺寸**：尽可能保持 16x16 或 32x32 像素每帧。

### 6.2 CEM 动画优化

- **骨骼数量**：减少不必要的骨骼数量，每增加一个骨骼都会增加矩阵计算量。
- **表达式简化**：避免使用复杂的数学表达式，尤其是三角函数和条件运算。
- **动画状态**：合理设计动画状态，避免多个状态同时激活。
- **混合时间**：设置合适的混合时间（0.1~0.3 秒），过长的混合会导致性能下降。
- **实例数量**：CEM 动画不会因为屏幕外实体而减少计算，大量实体同时动画会显著影响性能。

### 6.3 粒子动画优化

- **粒子数量**：限制同时存在的粒子数量。
- **纹理尺寸**：使用较小尺寸的粒子纹理。
- **生命周期**：较短的粒子生命周期可以减少总粒子数。

## 七、常见问题与解决方案

### 7.1 纹理动画不播放

**现象**：纹理在游戏中静止不动。

**检查清单**：
1. `.mcmeta` 文件命名是否正确（`<纹理名>.png.mcmeta`）。
2. JSON 格式是否正确（使用验证工具检查）。
3. `animations` 字段是否在正确的 JSON 路径（应位于 `animation` 键下）。
4. 纹理帧的尺寸是否正确计算。

### 7.2 动画速度不正确

**现象**：动画太快或太慢。

**调整方法**：
- `frametime` 值每增加 1，每帧显示时间增加 0.05 秒。
- 使用帧数组中的 `time` 属性单独调整特定帧的显示时间。
- 更高的 frametime = 更慢的动画。

### 7.3 CEM 动画不生效

**现象**：实体使用默认动画，自定义动画未应用。

**检查清单**：
1. 确认安装了 OptiFine 或 CEM 兼容模组。
2. `.jem` 文件路径是否正确（`assets/<命名空间>/optifine/cem/`）。
3. 动画状态配置是否正确。
4. 变量名是否正确（区分大小写）。
5. 查看日志文件（`.minecraft/logs/latest.log`）中的错误信息。

### 7.4 骨骼扭曲变形

**现象**：实体动画中出现模型扭曲或不自然变形。

**原因与解决**：
- 旋转轴心未正确设置，导致骨骼围绕错误的位置旋转。
- 父子骨骼关系错误，子骨骼受到父骨骼变换的叠加影响。
- 同时使用 translation 和 rotation 导致意料之外的组合变换。

### 7.5 动画闪烁或抖动

**现象**：动画播放过程中出现闪烁或抖动。

**原因与解决**：
- 纹理帧之间的色彩变化过大，减少相邻帧的颜色差异。
- 帧间插值导致像素采样位置不对齐，在像素风格纹理中禁用插值。
- 同时有多个纹理在相近区域产生变化，造成视觉干扰。

## 八、小结

动画是 Minecraft 资源包中最能提升视觉体验的元素之一。通过本指南的学习，你应当掌握了：

1. 纹理动画的制作方法，包括 `.mcmeta` 的完整配置。
2. CEM 实体动画系统的变量、表达式和关键帧系统。
3. 粒子动画的基本概念和配置方法。
4. 动画开发工具（特别是 Blockbench）的使用。
5. 动画性能优化的策略和技巧。

动画开发需要创意和技术的结合，建议从简单的纹理动画开始，逐步深入复杂的 CEM 实体动画，探索 Minecraft 资源包动画的无限可能性。
