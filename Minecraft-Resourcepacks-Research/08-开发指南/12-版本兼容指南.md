## pack_format 概述

### 什么是 pack_format

`pack_format` 是 Minecraft 资源包的核心版本标识，它位于 `pack.mcmeta` 文件中，告诉游戏该资源包是为哪个版本的 Minecraft 设计的。游戏会根据 `pack_format` 的值来决定如何加载和解析资源包中的内容。

```json
{
  "pack": {
    "pack_format": 34,
    "description": "我的资源包"
  }
}
```

### pack_format 的作用

```python
# pack_format 解析逻辑（简化）
def load_resource_pack(pack_path):
    """加载资源包并验证版本兼容性"""
    with open(os.path.join(pack_path, 'pack.mcmeta'), 'r') as f:
        pack_meta = json.load(f)

    pack_format = pack_meta['pack']['pack_format']

    # 游戏版本对应的 pack_format
    game_format = get_game_pack_format()

    if pack_format > game_format:
        print(f"警告: 资源包版本 ({pack_format}) 高于游戏版本 ({game_format})")
        print("某些功能可能不可用")
    elif pack_format < game_format:
        print(f"信息: 资源包版本 ({pack_format}) 低于游戏版本 ({game_format})")
        print("资源包将正常加载，但可能缺少新功能支持")
    else:
        print("资源包版本与游戏版本匹配")

    return pack_format

def get_game_pack_format():
    """获取当前游戏版本的 pack_format"""
    # 这里简化处理，实际游戏中由版本决定
    return 34  # 假设当前是 1.21.x
```

### pack_format 对资源加载的影响

不同 `pack_format` 值会影响游戏对资源的解析方式：

```
pack_format 影响示例：

1.12.2 (format=3) vs 1.13+ (format=4):

1.12.2 方块 ID:
  - minecraft:stone (data value 0-6)
  - minecraft:wool (data value 0-15)

1.13+ 方块 ID（扁平化后）:
  - minecraft:stone
  - minecraft:granite
  - minecraft:polished_granite
  - minecraft:wool (白色)
  - minecraft:orange_wool
  - minecraft:magenta_wool
```

## supported_formats 与版本范围

### supported_formats 语法

从较新版本的 Minecraft 开始，资源包可以在 `pack.mcmeta` 中声明支持的版本范围，而不是单一的 `pack_format` 值。

#### 基本语法

```json
{
  "pack": {
    "pack_format": 34,
    "description": "支持多版本的资源包",
    "supported_formats": {
      "min_inclusive": 15,
      "max_inclusive": 46
    }
  }
}
```

#### 支持的版本范围定义

```json
// 简写形式（数组）
{
  "pack": {
    "pack_format": 34,
    "supported_formats": [15, 46]
  }
}

// 完整形式（对象）
{
  "pack": {
    "pack_format": 34,
    "supported_formats": {
      "min_inclusive": 15,
      "max_inclusive": 46
    }
  }
}
```

### supported_formats 的行为

当游戏加载资源包时，会检查当前版本的 `pack_format` 是否在 `supported_formats` 范围内：

```python
def check_format_compatibility(pack_meta, game_format):
    """检查资源包与游戏版本的兼容性"""
    pack_format = pack_meta['pack']['pack_format']

    if 'supported_formats' in pack_meta['pack']:
        formats = pack_meta['pack']['supported_formats']

        if isinstance(formats, list):
            min_format, max_format = formats[0], formats[1]
        elif isinstance(formats, dict):
            min_format = formats.get('min_inclusive', 0)
            max_format = formats.get('max_inclusive', 999999)
        else:
            min_format = max_format = formats

        if min_format <= game_format <= max_format:
            return "兼容"
        elif game_format < min_format:
            return "游戏版本过低"
        else:
            return "游戏版本过高"
    else:
        # 没有 supported_formats，使用精确匹配
        if game_format == pack_format:
            return "兼容"
        elif game_format > pack_format:
            return "兼容（可能缺少新功能）"
        else:
            return "不兼容"
```

### 版本范围设计策略

#### 策略一：窄范围（推荐用于精细控制）

```json
{
  "pack": {
    "pack_format": 34,
    "supported_formats": {
      "min_inclusive": 34,
      "max_inclusive": 46
    }
  }
}
```

**适用场景**：
- 资源包使用了特定版本的新特性
- 需要精确控制兼容性
- 避免在不支持的版本上出现视觉问题

#### 策略二：宽范围（推荐用于最大兼容性）

```json
{
  "pack": {
    "pack_format": 34,
    "supported_formats": {
      "min_inclusive": 15,
      "max_inclusive": 64
    }
  }
}
```

**适用场景**：
- 资源包使用通用资源格式
- 希望支持尽可能多的版本
- 使用 Overlay 系统处理版本差异

#### 策略三：分代支持

```json
// 1.16-1.19 系列
{
  "pack": {
    "pack_format": 9,
    "supported_formats": {
      "min_inclusive": 6,
      "max_inclusive": 13
    }
  }
}

// 1.20+ 系列
{
  "pack": {
    "pack_format": 15,
    "supported_formats": {
      "min_inclusive": 15,
      "max_inclusive": 64
    }
  }
}
```

## Overlay 覆盖系统

### Overlay 系统概述

Overlay（覆盖）系统是 Minecraft 引入的一个强大特性，允许资源包为不同版本提供不同的资源内容。这使得一个资源包可以在多个版本上正确运行。

### Overlay 目录结构

```
my_resource_pack/
├── pack.mcmeta                    # 包元数据
├── pack.png
├── assets/                        # 基础资源（所有版本共用）
│   └── minecraft/
│       ├── textures/
│       │   └── block/
│       │       ├── stone.png
│       │       └── grass_block_side.png
│       └── models/
│           └── block/
│               └── stone.json
└── overlays/                      # 覆盖层
    ├── 1.19/                      # 1.19 版本特定资源
    │   └── assets/
    │       └── minecraft/
    │           └── textures/
    │               └── block/
    │                   └── sculk.png
    ├── 1.20/                      # 1.20 版本特定资源
    │   └── assets/
    │       └── minecraft/
    │           └── textures/
    │               └── block/
    │                   └── cherry_leaves.png
    └── 1.21/                      # 1.21 版本特定资源
        └── assets/
            └── minecraft/
                └── textures/
                    └── block/
                        └── tuff_bricks.png
```

```json
        },
        "directory": "overlays/1.20"
      },

        "formats": {
          "min_inclusive": 32,
          "max_inclusive": 64
        },
        "directory": "overlays/1.21"
```


### Overlay 优先级

Overlay 的加载优先级由 `entries` 数组中的顺序决定。后加载的 Overlay 会覆盖先加载的 Overlay 中的同名资源。

```json
{
  "overlays": {
    "entries": [
      {
        "formats": {"min_inclusive": 15, "max_inclusive": 32},
        "directory": "overlays/base"
      },
      {
        "formats": {"min_inclusive": 34, "max_inclusive": 64},
        "directory": "overlays/extended"
      }
    ]
  }
}
```

**优先级规则**：

```
资源加载顺序：

1. 基础资源 (assets/)
2. Overlay 1 (overlays/base/) - 如果版本匹配
3. Overlay 2 (overlays/extended/) - 如果版本匹配，覆盖 Overlay 1
```

### 条件 Overlay

条件 Overlay 允许根据版本特性选择性地加载资源：

```json
{
  "overlays": {
    "entries": [
      {
        "conditions": [
          {
            "type": "version",
            "value": {
              "min_inclusive": 34
            }
          }
        ],
        "directory": "overlays/1.21_plus"
      },
      {
        "conditions": [
          {
            "type": "version",
            "value": {
              "max_inclusive": 32
            }
          }
        ],
        "directory": "overlays/pre_1.21"
      }
    ]
  }
}
```

## 主要版本变更

### 1.13+ 扁平化更新 (The Flattening)

1.13 版本进行了 Minecraft 历史上最大的技术重构之一，称为"扁平化更新"。

#### 主要变更

```
扁平化更新核心变化：

1. 方块 ID 系统重构
   旧系统：使用数据值（data value）区分变体
   新系统：每个变体有独立的 ID

2. 示例：
   旧：minecraft:stone (data value: 0-6)
   新：minecraft:stone, minecraft:granite, minecraft:polished_granite,
       minecraft:diorite, minecraft:polished_diorite,
       minecraft:andesite, minecraft:polished_andesite

3. 物品 ID 变更
   旧：minecraft:log (data value: 0-3)
   新：minecraft:oak_log, minecraft:spruce_log,
       minecraft:birch_log, minecraft:jungle_log

4. 方块状态系统
   旧：使用 metadata 值
   新：使用 JSON 方块状态定义
```

#### 资源包影响

```json
// 1.12.2 方块状态 (blockstates/stone.json)
{
  "variants": {
    "variant=stone": {"model": "stone"},
    "variant=granite": {"model": "granite"},
    "variant=polished_granite": {"model": "polished_granite"}
  }
}

// 1.13+ 方块状态 (blockstates/stone.json)
{
  "variants": {
    "": {"model": "stone"}
  }
}

// 1.13+ 方块状态 (blockstates/granite.json)
{
  "variants": {
    "": {"model": "granite"}
  }
}
```

#### 迁移脚本

```python
# 1.12 -> 1.13 迁移工具
import os
import json
import shutil

def migrate_blockstates(old_dir, new_dir):
    """迁移方块状态文件"""
    os.makedirs(new_dir, exist_ok=True)

    # 方块 ID 映射表
    block_mapping = {
        'stone': {
            0: 'stone',
            1: 'granite',
            2: 'polished_granite',
            3: 'diorite',
            4: 'polished_diorite',
            5: 'andesite',
            6: 'polished_andesite'
        },
        'planks': {
            0: 'oak_planks',
            1: 'spruce_planks',
            2: 'birch_planks',
            3: 'jungle_planks',
            4: 'acacia_planks',
            5: 'dark_oak_planks'
        }
    }

    for filename in os.listdir(old_dir):
        if not filename.endswith('.json'):
            continue

        old_path = os.path.join(old_dir, filename)
        block_name = filename[:-5]  # 移除 .json 扩展名

        if block_name in block_mapping:
            with open(old_path, 'r') as f:
                old_state = json.load(f)

            # 为每个变体创建新的方块状态文件
            for data_value, new_name in block_mapping[block_name].items():
                new_state = {
                    "variants": {
                        "": old_state.get("variants", {}).get(
                            f"variant={block_name}",
                            {"model": f"block/{new_name}"}
                        )
                    }
                }

                new_path = os.path.join(new_dir, f"{new_name}.json")
                with open(new_path, 'w') as f:
                    json.dump(new_state, f, indent=2)
        else:
            # 没有映射的文件直接复制
            shutil.copy2(old_path, os.path.join(new_dir, filename))

def migrate_models(old_dir, new_dir):
    """迁移模型文件"""
    os.makedirs(new_dir, exist_ok=True)

    for filename in os.listdir(old_dir):
        if not filename.endswith('.json'):
            continue

        old_path = os.path.join(old_dir, filename)

        with open(old_path, 'r') as f:
            model = json.load(f)

        # 更新纹理引用
        if 'textures' in model:
            for key, texture in model['textures'].items():
                # 处理纹理路径变更
                if ':' not in texture:
                    model['textures'][key] = f"minecraft:block/{texture}"

        new_path = os.path.join(new_dir, filename)
        with open(new_path, 'w') as f:
            json.dump(model, f, indent=2)
```

## 多版本兼容策略

### 策略一：单版本资源包

为每个目标版本创建独立的资源包。

**优点**：
- 简单直接
- 每个版本的资源可以完全优化
- 不需要复杂的版本检测

**缺点**：
- 维护成本高
- 用户需要手动选择版本
- 文件大小翻倍

**适用场景**：
- 资源包使用了大量版本特定特性
- 需要为每个版本提供完全不同的体验
- 开发团队有足够的人力维护

### 策略二：宽版本范围 + Overlay

使用 `supported_formats` 声明宽版本范围，通过 Overlay 处理版本差异。

**优点**：
- 单一资源包支持多版本
- 自动适配版本
- 维护相对简单

**缺点**：
- 需要精心设计 Overlay 结构
- 文件大小可能增加
- 复杂的版本条件判断

**适用场景**：
- 希望一个资源包支持多个版本
- 版本差异主要是纹理或模型
- 愿意投入时间设计 Overlay 系统

```json
// 示例：使用 Overlay 的多版本资源包
{
  "pack": {
    "pack_format": 34,
    "description": "多版本兼容资源包",
    "supported_formats": {
      "min_inclusive": 15,
      "max_inclusive": 64
    }
  },
  "overlays": {
    "entries": [
      {
        "formats": {
          "min_inclusive": 15,
          "max_inclusive": 22
        },
        "directory": "overlays/1.20.0"
      },
      {
        "formats": {
          "min_inclusive": 32,
          "max_inclusive": 46
        },
        "directory": "overlays/1.20.5"
      },
      {
        "formats": {
          "min_inclusive": 57,
          "max_inclusive": 64
        },
        "directory": "overlays/1.21.5"
      }
    ]
  }
}
```

### 策略三：最小公分母

只使用所有目标版本都支持的特性，避免使用版本特定功能。

**优点**：
- 最大兼容性
- 简单的维护
- 小文件大小

**缺点**：
- 无法利用新版本特性
- 可能错过视觉改进
- 功能受限

**适用场景**：
- 需要支持非常老的版本
- 资源包内容简单
- 优先考虑兼容性而非特性

### 策略四：分支版本管理

使用 Git 分支管理不同版本的资源包。

```
Git 分支结构：

main
├── 1.16
├── 1.17
├── 1.18
├── 1.19
├── 1.20
└── 1.21
```

**优点**：
- 清晰的版本分离
- 可以为每个版本独立优化
- Git 工作流成熟

**缺点**：
- 合并变更复杂
- 需要同步多个分支
- 发布流程复杂

```python
# version_compatibility_checker.py
import os
import json

class VersionCompatibilityChecker:
    def __init__(self, pack_path):
        self.pack_path = pack_path
        self.issues = []
        self.warnings = []

    def check_pack_meta(self):
        """检查 pack.mcmeta 配置"""
        pack_meta_path = os.path.join(self.pack_path, 'pack.mcmeta')

        if not os.path.exists(pack_meta_path):
            self.issues.append("缺少 pack.mcmeta 文件")
            return None

        with open(pack_meta_path, 'r') as f:
            pack_meta = json.load(f)

        # 检查必需字段
        if 'pack' not in pack_meta:
            self.issues.append("pack.mcmeta 缺少 'pack' 字段")
            return None

        pack = pack_meta['pack']

        if 'pack_format' not in pack:
            self.issues.append("pack.mcmeta 缺少 'pack_format' 字段")

        if 'description' not in pack:
            self.warnings.append("pack.mcmeta 缺少 'description' 字段")

        return pack_meta

    def check_overlay_structure(self):
        """检查 Overlay 目录结构"""
        overlay_dir = os.path.join(self.pack_path, 'overlays')

        if not os.path.exists(overlay_dir):
            self.warnings.append("未使用 Overlay 系统")
            return

        pack_meta_path = os.path.join(self.pack_path, 'pack.mcmeta')
        with open(pack_meta_path, 'r') as f:
            pack_meta = json.load(f)

        if 'overlays' not in pack_meta:
            self.issues.append("存在 overlays 目录但 pack.mcmeta 中未配置 overlays")
            return

        overlays = pack_meta['overlays']

        if 'entries' not in overlays:
            self.issues.append("overlays 配置缺少 'entries' 字段")
            return

        for entry in overlays['entries']:
            if 'directory' not in entry:
                self.issues.append("overlay entry 缺少 'directory' 字段")
                continue

            entry_dir = os.path.join(self.pack_path, entry['directory'])
            if not os.path.exists(entry_dir):
                self.issues.append(f"overlay 目录不存在: {entry['directory']}")

    def check_resource_completeness(self):
        """检查资源完整性"""
        required_dirs = [
            'assets/minecraft/textures',
            'assets/minecraft/models',
            'assets/minecraft/blockstates'
        ]

        for dir_path in required_dirs:
            full_path = os.path.join(self.pack_path, dir_path)
            if not os.path.exists(full_path):
                self.warnings.append(f"缺少目录: {dir_path}")

    def generate_report(self):
        """生成检查报告"""
        print("=" * 60)
        print("版本兼容性检查报告")
        print("=" * 60)

        # 运行所有检查
        self.check_pack_meta()
        self.check_overlay_structure()
        self.check_resource_completeness()

        # 输出结果
        if self.issues:
            print("\n错误:")
            for issue in self.issues:
                print(f"  ✗ {issue}")

        if self.warnings:
            print("\n警告:")
            for warning in self.warnings:
                print(f"  ⚠ {warning}")

        if not self.issues and not self.warnings:
            print("\n✓ 所有检查通过")

# 使用示例
checker = VersionCompatibilityChecker("my_resource_pack/")
checker.generate_report()
```

### 版本转换工具

```python
# version_converter.py
import os
import json
import shutil

class VersionConverter:
    def __init__(self, pack_path):
        self.pack_path = pack_path

    def convert_format(self, target_format):
        """转换资源包到目标 pack_format"""
        pack_meta_path = os.path.join(self.pack_path, 'pack.mcmeta')

        with open(pack_meta_path, 'r') as f:
            pack_meta = json.load(f)

        old_format = pack_meta['pack']['pack_format']
        pack_meta['pack']['pack_format'] = target_format

        # 添加 supported_formats
        if 'supported_formats' not in pack_meta['pack']:
            pack_meta['pack']['supported_formats'] = {
                'min_inclusive': old_format,
                'max_inclusive': target_format
            }

        with open(pack_meta_path, 'w') as f:
            json.dump(pack_meta, f, indent=2)

        print(f"已转换: {old_format} -> {target_format}")

    def migrate_blockstates(self, source_version, target_version):
        """迁移方块状态文件"""
        # 版本特定的迁移规则
        migration_rules = self._get_migration_rules(source_version, target_version)

        blockstate_dir = os.path.join(self.pack_path, 'assets', 'minecraft', 'blockstates')

        for filename in os.listdir(blockstate_dir):
            if not filename.endswith('.json'):
                continue

            filepath = os.path.join(blockstate_dir, filename)
            block_name = filename[:-5]

            if block_name in migration_rules:
                new_name = migration_rules[block_name]
                new_filepath = os.path.join(blockstate_dir, f"{new_name}.json")

                if new_name != block_name:
                    os.rename(filepath, new_filepath)
                    print(f"迁移: {block_name} -> {new_name}")

    def _get_migration_rules(self, source_version, target_version):
        """获取版本迁移规则"""
        rules = {}

        # 1.12 -> 1.13 扁平化规则
        if source_version <= 12 and target_version >= 13:
            rules.update({
                'stone': 'stone',  # 保持，但内部变体已分离
                'log': 'oak_log',
                'log2': 'spruce_log',
                'planks': 'oak_planks',
                'wool': 'white_wool'
            })

        return rules

# 使用示例
converter = VersionConverter("my_resource_pack/")
converter.convert_format(34)
```

```python
# batch_version_adapter.py
import os
import json

def adapt_pack_for_versions(pack_path, versions):
    """批量适配资源包到多个版本"""
    results = {}

    for version in versions:
        print(f"\n适配版本: {version}")

        # 获取版本对应的 pack_format
        format_map = {
            '1.16': 6,
            '1.17': 7,
            '1.18': 8,
            '1.19': 9,
            '1.20': 15,
            '1.20.5': 32,
            '1.21': 34,
            '1.21.5': 57
        }

        target_format = format_map.get(version)
        if not target_format:
            print(f"  未知版本: {version}")
            continue

        # 创建版本特定的输出目录
        output_path = f"{pack_path}_{version}"
        if os.path.exists(output_path):
            shutil.rmtree(output_path)

        # 复制资源包
        shutil.copytree(pack_path, output_path)

        # 更新 pack.mcmeta
        converter = VersionConverter(output_path)
        converter.convert_format(target_format)

        results[version] = {
            'format': target_format,
            'path': output_path,
            'status': 'success'
        }

    return results

# 使用示例
results = adapt_pack_for_versions("my_resource_pack", ['1.18', '1.19', '1.20', '1.21'])
for version, info in results.items():
```

```python
# 版本特定纹理优化
def create_version_optimized_pack(base_pack_path, output_path, target_version):
    """为特定版本创建优化的资源包"""
    import shutil
    from PIL import Image

    # 复制基础资源包
    shutil.copytree(base_pack_path, output_path)

    # 版本特定的纹理尺寸配置
    texture_sizes = {
        '1.16': 16,  # 低配版本
        '1.17': 16,
        '1.18': 32,
        '1.19': 32,
        '1.20': 64,
        '1.21': 64   # 高配版本
    }

    max_size = texture_sizes.get(target_version, 32)

    # 优化纹理
    texture_dir = os.path.join(output_path, 'assets', 'minecraft', 'textures')

    for root, dirs, files in os.walk(texture_dir):
        for filename in files:
            if filename.endswith('.png'):
                filepath = os.path.join(root, filename)

                try:
                    img = Image.open(filepath)

                    if img.width > max_size or img.height > max_size:
                        ratio = min(max_size / img.width, max_size / img.height)
                        new_size = (int(img.width * ratio), int(img.height * ratio))
                        img = img.resize(new_size, Image.LANCZOS)
                        img.save(filepath, optimize=True)
                        print(f"优化: {filename} -> {new_size[0]}x{new_size[1]}")
                except Exception as e:
                    print(f"跳过 {filename}: {e}")
```

```python
import os
import json

class AutoVersionAdapter:
    def __init__(self, pack_path):
        self.pack_path = pack_path
        self.detected_version = None

    def detect_version(self):
        """自动检测资源包的目标版本"""

        with open(pack_meta_path, 'r') as f:
            pack_meta = json.load(f)

        pack_format = pack_meta['pack']['pack_format']

        # pack_format 到版本的映射

            6: '1.16',

            8: '1.18',
            9: '1.19',
            15: '1.20',
            34: '1.21',
            57: '1.21.5'
        }

        self.detected_version = format_to_version.get(pack_format, 'unknown')
        return self.detected_version

    def get_version_specific_fixes(self):
        """获取版本特定的修复建议"""
        fixes = []

        if self.detected_version == '1.16':
            fixes.append("建议添加下界更新方块纹理")
            fixes.append("检查是否有 1.13 扁平化前的遗留文件")

            fixes.append("建议添加潜声系列纹理")
            fixes.append("检查红树木系列纹理")

        return fixes

    def apply_fixes(self):

        fixes = self.get_version_specific_fixes()
```

```python
    # 添加 supported_formats 以保持向后兼容
    pack_meta['pack']['supported_formats'] = {
        'min_inclusive': old_format,
        'max_inclusive': target_format
    }

    with open(pack_meta_path, 'w') as f:
        json.dump(pack_meta, f, indent=2)

    print(f"已更新: {old_format} -> {target_format}")
```

### Q2：Overlay 文件不生效

**原因**：Overlay 配置错误或目录结构不正确

**解决方案**：

```
检查清单：

1. pack.mcmeta 中的 overlays 配置是否正确
2. 目录路径是否正确（相对于资源包根目录）
3. formats 范围是否覆盖当前游戏版本

```

### Q3：如何支持非常老的版本（1.12 之前）

### Q4：如何处理版本间的模型格式差异

**原因**：不同版本的模型 JSON 格式可能有差异

**解决方案**：

```python
def adapt_model_for_version(model_path, target_version):
    """适配模型到特定版本"""
    with open(model_path, 'r') as f:
        model = json.load(f)

    # 1.13+ 的纹理引用格式变更
    if target_version >= 13:
        if 'textures' in model:
            for key, texture in model['textures'].items():
                if '/' in texture and ':' not in texture:
                    # 添加命名空间
                    model['textures'][key] = f"minecraft:block/{texture}"

    # 1.14+ 的显示设置
    if target_version >= 14:
        if 'display' not in model:
            model['display'] = self._get_default_display()

    return model
```

### Q5：Overlay 系统增加了太多文件大小

**原因**：每个 Overlay 可能包含大量重复资源

**解决方案**：

```
优化策略：

1. 只在 Overlay 中放置版本特定的资源
   - 基础资源放在 assets/ 目录
   - 只有版本差异放在 overlays/ 目录

2. 使用增量 Overlay
   - 只覆盖有变化的文件
   - 避免完整复制整个资源目录

3. 压缩 Overlay 文件
   - 使用优化的 PNG 格式
   - 减少不必要的纹理帧
```

## 总结

版本兼容是 Minecraft 资源包开发中的重要挑战。随着 Minecraft 不断更新，资源包需要适应新的格式、新的方块和新的特性。本指南提供了全面的版本兼容开发策略：

### 关键要点

1. **理解 pack_format**：它是资源包版本的核心标识，决定了游戏如何加载资源

2. **善用 supported_formats**：声明版本范围可以让资源包在多个版本上工作

3. **Overlay 系统是关键**：通过 Overlay 可以为不同版本提供不同的资源，实现真正的多版本兼容

4. **了解主要版本变更**：1.13 扁平化、1.16 下界更新、1.17 洞穴更新等都是重要的转折点

5. **选择合适的兼容策略**：根据资源包复杂度和目标版本范围选择单版本、宽范围、最小公分母或分支管理策略

### 最佳实践

```
版本兼容最佳实践：

1. 从最新版本开始开发
   - 使用最新的 pack_format
   - 利用新版本的特性

2. 向后兼容时使用 Overlay
   - 为旧版本提供适配资源
   - 保持基础资源不变

3. 充分测试
   - 在所有目标版本上测试
   - 检查资源完整性

4. 清晰的文档
   - 说明支持的版本范围
   - 列出已知的兼容性问题

5. 持续维护
   - 跟踪 Minecraft 更新
   - 及时适配新版本
```

通过本指南的学习，你应该能够创建支持多个 Minecraft 版本的资源包，并为未来的版本更新做好准备。记住，版本兼容是一个持续的过程，需要定期更新和维护。
