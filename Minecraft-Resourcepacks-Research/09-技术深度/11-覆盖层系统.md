## 1. 概述

覆盖层系统（Overlay System）是 Minecraft Java Edition 1.20.2 版本引入的一项重要特性，它允许资源包根据游戏版本或特定条件动态选择不同的资源文件。这一系统极大地简化了多版本兼容资源包的开发和维护。

### 1.1 覆盖层的核心价值

在覆盖层系统出现之前，多版本兼容的资源包通常需要：

- 维护多个独立的资源包版本
- 使用复杂的构建脚本自动生成不同版本
- 依赖模组（如 Forge/Fabric）的版本兼容机制

覆盖层系统通过在单个资源包内支持版本特定的资源覆盖，解决了这些问题。

### 1.2 覆盖层的工作原理

```
资源包根目录
├── pack.mcmeta                    # 覆盖层定义
├── assets/                        # 基础资源（默认版本）
│   └── minecraft/
│       ├── textures/
│       ├── models/
│       ├── sounds.json
│       └── ...
│
├── overlay_1.20.2/                # 1.20.2 版本覆盖层
│   └── assets/minecraft/
│       └── ...（仅需要修改的文件）
│
└── overlay_1.21/                  # 1.21 版本覆盖层
    └── assets/minecraft/
        └── ...（仅需要修改的文件）
```

**加载流程**：
1. 游戏读取 `pack.mcmeta` 中的覆盖层定义
2. 根据当前游戏版本确定适用的覆盖层
3. 加载基础资源（`assets/`）
4. 按优先级顺序应用覆盖层中的资源
5. 最终资源 = 基础资源 + 覆盖层资源

## 2. 覆盖层基础概念

### 2.1 什么是覆盖层

覆盖层（Overlay）是一组位于特殊命名目录中的资源文件，它们会在特定条件下覆盖或补充基础资源。覆盖层目录的名称遵循特定的命名约定，包含了版本范围或条件信息。

### 2.2 覆盖层类型

| 类型 | 目录命名格式 | 说明 |
|------|-------------|------|
| 版本覆盖层 | `overlay_<min>_<max>` | 在指定版本范围内激活 |
| 条件覆盖层 | `overlay_<condition>` | 基于特定条件激活 |

### 2.3 覆盖层与基础资源的关系

```
优先级（从低到高）：
基础资源（assets/） → 覆盖层1 → 覆盖层2 → ... → 覆盖层N

最终资源 = 基础资源被所有适用覆盖层逐步覆盖后的结果
```

**关键特性**：
- 覆盖层只包含需要修改的文件
- 覆盖层可以添加新文件
- 覆盖层可以覆盖已有文件
- 多个覆盖层可以叠加

## 3. 目录结构规范

### 3.1 标准覆盖层目录结构

```
MyResourcePack/
├── pack.mcmeta                        # 资源包元数据（必须）
├── pack.png                           # 资源包图标
│
├── assets/                            # 基础资源目录
│   └── minecraft/
│       ├── blockstates/
│       ├── models/
│       ├── textures/
│       │   ├── block/
│       │   ├── item/
│       │   └── ...
│       ├── sounds/
│       ├── sounds.json
│       ├── lang/
│       ├── font/
│       ├── shaders/
│       └── ...
│
├── overlay_1.20.2/                    # 1.20.2 版本覆盖层
│   └── assets/
│       └── minecraft/
│           ├── textures/
│           │   └── block/
│           │       └── new_texture.png
│           └── models/
│               └── block/
│                   └── updated_model.json
│
├── overlay_1.20.3_1.20.4/            # 1.20.3-1.20.4 版本范围覆盖层
│   └── assets/
│       └── minecraft/
│           └── ...
│
└── overlay_1.21/                      # 1.21+ 版本覆盖层
    └── assets/
        └── minecraft/
            └── ...
```

### 3.2 覆盖层目录命名规则

#### 版本范围格式

```
overlay_<min_version>_<max_version>
```

**示例**：
```
overlay_1.20.2              # 仅 1.20.2
overlay_1.20.2_1.20.4       # 1.20.2 到 1.20.4（包含）
overlay_1.21_               # 1.21 及以上（无上限）
overlay__1.20.4             # 1.20.4 及以下（无下限）
```

**版本号格式**：
- 使用下划线 `_` 分隔主版本、次版本和修订版本
- 使用点 `.` 分隔版本段内的数字
- 示例：`1.20.2` 表示版本 1.20.2

**版本范围语法**：
| 格式 | 含义 | 示例 |
|------|------|------|
| `X.Y.Z` | 精确版本 | `overlay_1.20.2` = 仅 1.20.2 |
| `X.Y.Z_X.Y.W` | 版本范围 | `overlay_1.20.2_1.20.4` = 1.20.2 到 1.20.4 |
| `X.Y.Z_` | 最小版本 | `overlay_1.21_` = 1.21 及以上 |
| `_X.Y.Z` | 最大版本 | `overlay__1.20.4` = 1.20.4 及以下 |

### 3.3 命名规范详解

#### 版本号解析

```
overlay_1.20.2_1.21.1
       ├───┤ ├───┤
        min   max

min = 1.20.2（包含）
max = 1.21.1（包含）
```

#### 分隔符规则

- **版本段分隔符**：使用点 `.`（如 `1.20.2`）
- **min-max 分隔符**：使用下划线 `_`（如 `1.20.2_1.21`）
- **目录前缀**：使用 `overlay_`（必须）

#### 有效命名示例

```
overlay_1.20.2                    ✓ 有效
overlay_1.20.2_1.20.4             ✓ 有效
overlay_1.21_                     ✓ 有效
overlay__1.20.4                   ✓ 有效
overlay_1.20.2_1.21.1             ✓ 有效

overlay-1.20.2                    ✗ 无效（使用了连字符）
overlay_1.20.2.1                  ✗ 无效（版本格式错误）
1.20.2_overlay                    ✗ 无效（前缀位置错误）
overlay_1.20.2_to_1.21            ✗ 无效（使用了 "to"）
```

## 4. 版本覆盖层

### 4.1 版本覆盖层定义

版本覆盖层根据游戏版本激活。当游戏版本落在覆盖层指定的版本范围内时，该覆盖层中的资源会被加载并覆盖基础资源。

### 4.2 版本范围格式详解

#### 精确版本

```json
// pack.mcmeta
{
    "pack": {
        "pack_format": 22,
        "description": "My Resource Pack"
    },
    "overlays": {
        "entries": [
            {
                "formats": {
                    "min_inclusive": 22,
                    "max_inclusive": 22
                },
                "directory": "overlay_1.20.2"
            }
        ]
    }
}
```

对应的目录结构：
```
overlay_1.20.2/
└── assets/
    └── minecraft/
        └── ...
```

#### 版本范围

```json
{
    "overlays": {
        "entries": [
            {
                "formats": {
                    "min_inclusive": 18,
                    "max_inclusive": 22
                },
                "directory": "overlay_1.20_1.20.4"
            }
        ]
    }
}
```

**注意**：`formats` 使用的是 `pack_format` 数值，而非游戏版本号。

### 4.3 pack_format 版本对照表

| 游戏版本 | pack_format |
|---------|-------------|
| 1.20 - 1.20.1 | 15 |
| 1.20.2 | 18 |
| 1.20.3 - 1.20.4 | 22 |
| 1.20.5 - 1.20.6 | 32 |
| 1.21 - 1.21.1 | 34 |
| 1.21.2 - 1.21.3 | 42 |
| 1.21.4 | 46 |
| 1.21.5 | 57 |
| 1.21.6 | 64 |
| 1.21.7+ | 65+ |

### 4.4 版本范围表达式

#### 最小版本（无上限）

```json
{
    "formats": {
        "min_inclusive": 34
    },
    "directory": "overlay_1.21_"
}
```

表示 1.21 及以上所有版本。

#### 最大版本（无下限）

```json
{
    "formats": {
        "max_inclusive": 22
    },
    "directory": "overlay__1.20.4"
}
```

表示 1.20.4 及以下所有版本。

#### 闭区间范围

```json
{
    "formats": {
        "min_inclusive": 18,
        "max_inclusive": 22
    },
    "directory": "overlay_1.20.2_1.20.4"
}
```

表示 1.20.2 到 1.20.4 之间的所有版本（包含两端）。

### 4.5 版本覆盖层文件组织

**只包含需要修改的文件**：

```
overlay_1.21/
└── assets/
    └── minecraft/
        ├── textures/
        │   └── block/
        │       └── new_block_1.21.png    # 1.21 新增的方块纹理
        ├── models/
        │   └── block/
        │       └── new_block_1.21.json   # 1.21 新增的方块模型
        └── sounds.json                   # 1.21 新增的声音事件（可以是完整文件或补丁）
```

**不要复制整个 assets 目录**：覆盖层只需要包含与基础版本不同的文件。

## 5. 条件覆盖层

### 5.1 条件覆盖层概念

条件覆盖层（Conditional Overlay）根据非版本因素激活。虽然 Minecraft 原生主要支持基于 `pack_format` 的条件覆盖，但资源包可以实现自定义条件逻辑。

### 5.2 功能特性覆盖

条件覆盖层可以基于功能特性（Feature Flags）激活：

```json
{
    "pack": {
        "pack_format": 34,
        "description": "My Resource Pack",
        "supported_formats": {
            "min_inclusive": 15,
            "max_inclusive": 100
        },
        "features": [
            "vanilla",
            "trade_rebalance"
        ]
    },
    "overlays": {
        "entries": [
            {
                "formats": {
                    "min_inclusive": 15,
                    "max_inclusive": 100
                },
                "directory": "overlay_trade_rebalance",
                "conditions": [
                    {
                        "type": "feature_flag",
                        "flag": "trade_rebalance"
                    }
                ]
            }
        ]
    }
}
```

**可用的特性标志**：
- `vanilla` - 原版特性
- `trade_rebalance` - 交易平衡实验性特性
- `bundle` - 物品捆绑实验性特性

### 5.3 自定义条件逻辑

虽然 `pack.mcmeta` 不直接支持自定义条件，但可以通过以下方式实现：

#### 方式一：多个资源包组合

创建多个资源包，根据需要启用/禁用特定包。

#### 方式二：模组辅助

使用模组读取自定义配置，动态加载资源。

#### 方式三：构建脚本

使用构建脚本根据条件生成最终的资源包。

### 5.4 条件覆盖层优先级

当多个条件覆盖层同时满足条件时，按照 `entries` 数组中的顺序依次应用。

```json
{
    "overlays": {
        "entries": [
            {
                "formats": { "min_inclusive": 18 },
                "directory": "overlay_base",
                "conditions": [...]
            },
            {
                "formats": { "min_inclusive": 22 },
                "directory": "overlay_extended",
                "conditions": [...]
            }
        ]
    }
}
```

## 6. pack.mcmeta 配置详解

### 6.1 完整格式规范

```json
{
    "pack": {
        "pack_format": 34,
        "description": [
            {
                "text": "My Resource Pack ",
                "color": "green"
            },
            {
                "text": "v2.0",
                "color": "gold",
                "bold": true
            }
        ],
        "supported_formats": {
            "min_inclusive": 15,
            "max_inclusive": 100
        },
        "features": [
            "vanilla"
        ]
    },
    "overlays": {
        "entries": [
            {
                "formats": {
                    "min_inclusive": 18,
                    "max_inclusive": 22
                },
                "directory": "overlay_1.20.2_1.20.4"
            },
            {
                "formats": {
                    "min_inclusive": 22,
                    "max_inclusive": 32
                },
                "directory": "overlay_1.20.3_1.20.6"
            },
            {
                "formats": {
                    "min_inclusive": 34
                },
                "directory": "overlay_1.21_"
            }
        ]
    }
}
```

### 6.2 字段详解

#### `pack` 对象

| 字段 | 类型 | 必须 | 说明 |
|------|------|------|------|
| `pack_format` | `int` | 是 | 当前资源包格式版本 |
| `description` | `string\|array` | 是 | 资源包描述（支持原始JSON文本） |
| `supported_formats` | `object` | 否 | 支持的格式范围 |
| `features` | `string[]` | 否 | 启用的功能特性 |

#### `pack.supported_formats` 对象

| 字段 | 类型 | 说明 |
|------|------|------|
| `min_inclusive` | `int` | 最小支持的 pack_format |
| `max_inclusive` | `int` | 最大支持的 pack_format |

```json
{
    "supported_formats": {
        "min_inclusive": 15,
        "max_inclusive": 100
    }
}
```

这表示资源包支持 pack_format 从 15 到 100 的所有版本。

**简写形式**（单一值）：
```json
{
    "supported_formats": 34
}
```
等价于：
```json
{
    "supported_formats": {
        "min_inclusive": 34,
        "max_inclusive": 34
    }
}
```

#### `pack.features` 数组

列出资源包启用的实验性功能特性。

```json
{
    "features": [
        "vanilla",
        "trade_rebalance",
        "bundle"
    ]
}
```

#### `overlays` 对象

| 字段 | 类型 | 必须 | 说明 |
|------|------|------|------|
| `entries` | `array` | 是 | 覆盖层条目列表 |

#### `overlays.entries[]` 对象

| 字段 | 类型 | 必须 | 说明 |
|------|------|------|------|
| `formats` | `object\|int` | 是 | 激活的 pack_format 范围 |
| `directory` | `string` | 是 | 覆盖层目录名称 |
| `conditions` | `array` | 否 | 附加激活条件 |

#### `overlays.entries[].formats` 对象

| 字段 | 类型 | 说明 |
|------|------|------|
| `min_inclusive` | `int` | 最小 pack_format（包含） |
| `max_inclusive` | `int` | 最大 pack_format（包含） |

```json
// 闭区间范围
"formats": {
    "min_inclusive": 18,
    "max_inclusive": 22
}

// 仅最小值（无上限）
"formats": {
    "min_inclusive": 34
}

// 仅最大值（无下限）
"formats": {
    "max_inclusive": 22
}

// 单一值
"formats": 34
```

### 6.3 覆盖层条目排序

覆盖层条目的顺序很重要，它们按照数组中的顺序依次应用。

```json
{
    "overlays": {
        "entries": [
            {
                "formats": { "min_inclusive": 18 },
                "directory": "overlay_1.20.2_"  // 先应用
            },
            {
                "formats": { "min_inclusive": 22 },
                "directory": "overlay_1.20.3_"  // 后应用（优先级更高）
            },
            {
                "formats": { "min_inclusive": 34 },
                "directory": "overlay_1.21_"     // 最后应用（最高优先级）
            }
        ]
    }
}
```

## 7. 加载逻辑与优先级

### 7.1 加载流程详解

```
1. 游戏启动，读取资源包
   │
2. 解析 pack.mcmeta
   ├── 读取 pack.supported_formats
   ├── 验证当前版本是否在支持范围内
   └── 解析 overlays.entries
   │
3. 确定适用的覆盖层
   ├── 对每个 entry 检查 formats 范围
   ├── 检查 conditions 条件
   └── 生成适用覆盖层列表（按 entries 顺序）
   │
4. 加载基础资源
   └── 读取 assets/ 目录中的所有文件
   │
5. 应用覆盖层（按顺序）
   ├── 第一个覆盖层：覆盖基础资源中同路径的文件
   ├── 第二个覆盖层：覆盖前一步结果中同路径的文件
   └── ...直到所有覆盖层应用完毕
   │
6. 最终资源就绪
```

### 7.2 优先级规则

**基本规则**：
```
覆盖层优先级 = entries 数组中的索引（越靠后优先级越高）

最终优先级：基础资源 < 覆盖层1 < 覆盖层2 < ... < 覆盖层N
```

**示例**：
```json
{
    "overlays": {
        "entries": [
            {
                "formats": { "min_inclusive": 18 },
                "directory": "overlay_low_priority"    // 优先级较低
            },
            {
                "formats": { "min_inclusive": 18 },
                "directory": "overlay_high_priority"   // 优先级较高
            }
        ]
    }
}
```

当两个覆盖层都激活且修改了同一文件时，`overlay_high_priority` 中的文件会覆盖 `overlay_low_priority` 中的文件。

### 7.3 文件合并规则

#### 完整文件覆盖

覆盖层中的文件会完全替换基础资源中同路径的文件。

```
基础资源：assets/minecraft/textures/block/stone.png
覆盖层：  overlay_1.21_/assets/minecraft/textures/block/stone.png

结果：使用覆盖层中的 stone.png
```

#### 新增文件

覆盖层可以添加基础资源中不存在的文件。

```
基础资源：（不存在 new_block.png）
覆盖层：  overlay_1.21_/assets/minecraft/textures/block/new_block.png

结果：新增 new_block.png
```

#### JSON 文件合并

对于 JSON 文件，覆盖层会完全替换而非合并。

```
基础资源：{ "a": 1, "b": 2 }
覆盖层：  { "c": 3 }

结果：{ "c": 3 }  （不是 { "a": 1, "b": 2, "c": 3 }）
```

### 7.4 版本匹配算法

```
对于每个覆盖层 entry：
    1. 检查 formats.min_inclusive（如果存在）
       - 如果当前 pack_format < min_inclusive → 不适用
    2. 检查 formats.max_inclusive（如果存在）
       - 如果当前 pack_format > max_inclusive → 不适用
    3. 检查 conditions（如果存在）
       - 所有条件必须满足
    4. 如果通过所有检查 → 适用此覆盖层
```

**示例**：
```
当前游戏版本：1.21 (pack_format = 34)

overlay_1.20.2_1.20.4:
  formats: { min: 18, max: 22 }
  34 > 22 → 不适用 ✗

overlay_1.20.3_1.20.6:
  formats: { min: 22, max: 32 }
  34 > 32 → 不适用 ✗

overlay_1.21_:
  formats: { min: 34 }
  34 >= 34 → 适用 ✓

结果：只有 overlay_1.21_ 被激活
```

### 7.5 重叠版本范围

当多个覆盖层的版本范围重叠时，它们都会被激活：

```
当前版本：1.20.3 (pack_format = 22)

overlay_1.20.2_1.20.4:
  formats: { min: 18, max: 22 }
  22 在范围内 → 适用 ✓

overlay_1.20.3_1.20.6:
  formats: { min: 22, max: 32 }
  22 在范围内 → 适用 ✓

overlay_1.21_:
  formats: { min: 34 }
  22 < 34 → 不适用 ✗

结果：overlay_1.20.2_1.20.4 和 overlay_1.20.3_1.20.6 都被激活
优先级：overlay_1.20.3_1.20.6 > overlay_1.20.2_1.20.4（后定义的优先级更高）
```

## 8. 多版本兼容方案

### 8.1 方案一：全面覆盖层

为每个支持的版本创建单独的覆盖层。

**优点**：
- 结构清晰
- 每个版本的修改独立
- 易于维护

**缺点**：
- 文件数量多
- 需要维护多个目录

**适用场景**：大型资源包，版本间差异大

```
MyResourcePack/
├── pack.mcmeta
├── assets/                            # 通用基础资源
│   └── minecraft/
│       └── ...
│
├── overlay_1.20_1.20.1/              # 1.20-1.20.1
│   └── assets/minecraft/
│       └── ...
│
├── overlay_1.20.2_1.20.4/            # 1.20.2-1.20.4
│   └── assets/minecraft/
│       └── ...
│
├── overlay_1.20.5_1.20.6/            # 1.20.5-1.20.6
│   └── assets/minecraft/
│       └── ...
│
└── overlay_1.21_/                     # 1.21+
    └── assets/minecraft/
        └── ...
```

### 8.2 方案二：差异最小化

只在基础资源中放置最通用的资源，将版本差异放入覆盖层。

**优点**：
- 基础资源最小化
- 覆盖层只包含差异
- 总体文件量小

**缺点**：
- 需要仔细规划基础资源
- 版本差异不明显

**适用场景**：小型资源包，版本间差异小

```
MyResourcePack/
├── pack.mcmeta
├── assets/
│   └── minecraft/
│       └── textures/
│           └── block/
│               └── common_texture.png   # 所有版本通用
│
├── overlay_1.20.2_1.20.4/
│   └── assets/minecraft/textures/block/
│       └── version_specific.png         # 仅 1.20.2-1.20.4 使用
│
└── overlay_1.21_/
    └── assets/minecraft/textures/block/
        └── new_texture.png              # 1.21+ 新增
```

### 8.3 方案三：渐进式增强

基础资源支持最旧版本，覆盖层逐步添加新版本的特性。

**优点**：
- 基础资源稳定
- 新版本特性隔离
- 向后兼容性好

**缺点**：
- 可能有冗余文件
- 需要理解版本特性

**适用场景**：长期维护的资源包

```json
{
    "pack": {
        "pack_format": 46,
        "description": "Progressive enhancement pack"
    },
    "overlays": {
        "entries": [
            {
                "formats": { "min_inclusive": 22 },
                "directory": "overlay_1.20.3_enhancements"
            },
            {
                "formats": { "min_inclusive": 32 },
                "directory": "overlay_1.20.5_enhancements"
            },
            {
                "formats": { "min_inclusive": 34 },
                "directory": "overlay_1.21_enhancements"
            },
            {
                "formats": { "min_inclusive": 46 },
                "directory": "overlay_1.21.4_enhancements"
            }
        ]
    }
}
```

### 8.4 方案四：关键版本支持

只为有重大变更的关键版本创建覆盖层。

**优点**：
- 维护工作量小
- 覆盖层数量少
- 聚焦重要变更

**缺点**：
- 某些版本可能不完全兼容
- 需要识别关键版本

**适用场景**：快速迭代的资源包

**关键版本识别**：
- 模型格式变更版本
- 纹理变更版本
- 声音系统变更版本
- 着色器变更版本

### 8.5 版本兼容性检查清单

创建多版本兼容资源包时的检查清单：

```
□ 识别需要支持的版本范围
□ 确定每个版本的 pack_format
□ 分析版本间的资源差异
□ 设计基础资源结构
□ 规划覆盖层目录
□ 创建 pack.mcmeta 配置
□ 测试每个目标版本
□ 验证覆盖层优先级
□ 检查文件路径一致性
□ 测试版本切换场景
```

## 9. 最佳实践

### 9.1 目录组织最佳实践

#### 实践一：清晰的版本划分

```
推荐：
overlay_1.20.2_1.20.4/
overlay_1.20.5_1.20.6/
overlay_1.21_/

不推荐：
overlay_v2/
overlay_latest/
overlay_new/
```

#### 实践二：最小化覆盖层内容

```
推荐（只包含差异文件）：
overlay_1.21_/
└── assets/minecraft/textures/block/
    └── new_block.png

不推荐（复制整个 assets）：
overlay_1.21_/
└── assets/minecraft/
    ├── textures/  (所有纹理)
    ├── models/    (所有模型)
    └── ...
```

#### 实践三：保持路径一致性

```
基础资源：assets/minecraft/textures/block/stone.png
覆盖层：  overlay_1.21_/assets/minecraft/textures/block/stone.png
                             ↑ 路径必须一致

错误示例：
覆盖层：  overlay_1.21_/minecraft/textures/block/stone.png
                             ↑ 缺少 assets 前缀
```

### 9.2 命名规范最佳实践

#### 版本号格式

```
推荐：overlay_1.20.2_1.20.4
不推荐：overlay_v1.20.2_to_v1.20.4
不推荐：overlay_1202_1204
```

#### 语义化命名

```
推荐：
overlay_1.20.2_1.20.4/    # 清晰的版本范围
overlay_1.21_/            # 明确的最小版本

不推荐：
overlay_v1/
overlay_v2/
overlay_patch/
```

### 9.3 配置管理最佳实践

#### 实践一：明确的 supported_formats

```json
{
    "pack": {
        "pack_format": 34,
        "supported_formats": {
            "min_inclusive": 15,
            "max_inclusive": 100
        }
    }
}
```

**说明**：使用宽泛的 `supported_formats` 确保资源包在更多版本中被识别，让覆盖层处理具体的版本差异。

#### 实践二：覆盖层顺序规划

```json
{
    "overlays": {
        "entries": [
            {
                "formats": { "min_inclusive": 15 },
                "directory": "overlay_base"
            },
            {
                "formats": { "min_inclusive": 22 },
                "directory": "overlay_enhanced"
            },
            {
                "formats": { "min_inclusive": 34 },
                "directory": "overlay_latest"
            }
        ]
    }
}
```

**说明**：按版本从旧到新排列覆盖层，确保新版本覆盖层的优先级更高。

#### 实践三：版本范围不重叠（推荐）

```json
{
    "entries": [
        { "formats": { "min_inclusive": 15, "max_inclusive": 17 } },
        { "formats": { "min_inclusive": 18, "max_inclusive": 21 } },
        { "formats": { "min_inclusive": 22, "max_inclusive": 31 } },
        { "formats": { "min_inclusive": 32 } }
    ]
}
```

**说明**：虽然重叠是允许的，但不重叠的范围更容易理解和维护。

## 11. 常见问题与排错

```json
{
    "overlays": {
        "entries": [
            {
                "formats": {
                    "min_inclusive": 18,  // 确认 pack_format 正确
                    "max_inclusive": 22
                },
                "directory": "overlay_1.20.2_1.20.4"  // 确认与目录名一致
            }
        ]
    }
}
```

3. **版本匹配**
```bash
# 检查当前游戏的 pack_format
# 在游戏中按 F3 调试屏幕查看
```

4. **文件路径一致性**
```
覆盖层中的路径必须与基础资源中的路径完全一致

基础：assets/minecraft/textures/block/stone.png
```

### 11.2 多个覆盖层冲突

**症状**：文件被意外覆盖

**解决方案**：

1. **检查覆盖层优先级**
```json
{
    "overlays": {
        "entries": [
            { "formats": { "min_inclusive": 18 }, "directory": "overlay_low" },
            { "formats": { "min_inclusive": 18 }, "directory": "overlay_high" }
            // overlay_high 优先级更高
        ]
    }
}
```

2. **避免版本范围重叠**（如果不需要）
```json
{
    "entries": [
        { "formats": { "min_inclusive": 18, "max_inclusive": 22 } },
        { "formats": { "min_inclusive": 23, "max_inclusive": 32 } },
        { "formats": { "min_inclusive": 33 } }
    ]
}
```

### 11.3 pack.mcmeta 语法错误

**症状**：资源包无法加载

**常见错误**：

```json
        "description": "test"  // 缺少逗号
    }

    }

    }
```

## 12. 高级技巧

### 12.1 动态资源选择

虽然覆盖层系统本身是静态的，但可以结合其他机制实现动态效果。

**方法一：使用多个资源包**

### 12.2 条件化覆盖层

```json
{

            }

    }
}
```

### 12.3 覆盖层与资源包堆叠

覆盖层系统与资源包堆叠（Resource Pack Stacking）可以结合使用：

```
资源包加载顺序（从低到高）：
1. 默认资源包
2. 资源包A（带覆盖层）
3. 资源包B（带覆盖层）
4. 资源包C（带覆盖层）

每个资源包的覆盖层独立处理
最终资源 = 默认资源 + A(基础+覆盖层) + B(基础+覆盖层) + C(基础+覆盖层)
```

### 12.4 自动化构建

使用构建脚本自动生成覆盖层：

```python
# Python 示例
import os
import json
import shutil

def create_overlay_pack(base_dir, versions):
    """创建带覆盖层的资源包"""
    
    # 创建基础 pack.mcmeta
    pack_mcmeta = {
        "pack": {
            "pack_format": 34,
            "description": "Auto-generated multi-version pack"
        },
        "overlays": {
            "entries": []
        }
    }
    
    for version_info in versions:
        version = version_info['version']
        min_format = version_info['min_format']
        max_format = version_info.get('max_format')
        
        # 创建覆盖层目录
        overlay_dir = f"overlay_{version}"
        os.makedirs(os.path.join(base_dir, overlay_dir, "assets/minecraft"), exist_ok=True)
        
        # 复制版本特定文件
        # ...
        
        # 添加覆盖层条目
        entry = {
            "formats": {
                "min_inclusive": min_format
            },
            "directory": overlay_dir
        }
        if max_format:
            entry["formats"]["max_inclusive"] = max_format
        
        pack_mcmeta["overlays"]["entries"].append(entry)
    
    # 写入 pack.mcmeta
    with open(os.path.join(base_dir, "pack.mcmeta"), "w") as f:
        json.dump(pack_mcmeta, f, indent=2)

# 使用
versions = [
    {"version": "1.20.2_1.20.4", "min_format": 18, "max_format": 22},
    {"version": "1.20.5_1.20.6", "min_format": 32, "max_format": 33},
    {"version": "1.21_", "min_format": 34},
]

create_overlay_pack("MyResourcePack", versions)
```
