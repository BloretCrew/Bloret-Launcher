# 纹理制作规范

## 概述

纹理是 Minecraft 资源包中最基础也是最重要的组成元素。本文档详细阐述 Minecraft 纹理制作的完整技术规格，涵盖尺寸标准、文件格式、色彩规范、透明度处理、布局规范、动画系统、命名约定以及优化策略。

---

## 1. 尺寸标准

### 1.1 原生分辨率

Minecraft 的原生纹理分辨率为 **16×16 像素**。这是游戏设计的基准分辨率，所有原版纹理均以此尺寸制作。

### 1.2 高清纹理分辨率

高清资源包通常采用以下倍率放大：

| 倍率 | 纹理尺寸 | 常见名称 | 适用场景 |
|------|----------|----------|----------|
| 1x | 16×16 | 原生（Native） | 原版风格 |
| 2x | 32×32 | 半高清（SD） | 轻微提升清晰度 |
| 4x | 64×64 | 高清（HD） | 常见高清包 |
| 8x | 128×128 | 全高清（FHD） | 高质量资源包 |
| 16x | 256×256 | 超高清（QHD） | 顶级质量资源包 |
| 32x | 512×512 | 极高清（UHD） | 极致画质需求 |
| 64x | 1024×1024 | 超极致 | 仅用于特殊展示 |

### 1.3 尺寸约束规则

**必须为2的幂次方（Power of Two）**：Minecraft 的纹理系统要求所有纹理的宽度和高度必须是 2 的幂次方（1, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024...）。

**宽高比**：
- 方块纹理：必须为正方形（1:1），如 16×16、32×32
- 物品纹理：必须为正方形（1:1）
- 实体纹理：通常为矩形，宽度 ≥ 高度，且宽度是高度的整数倍
- GUI 纹理：根据设计需要，但必须符合 2 的幂次方规则

**Mipmap 兼容性**：为确保 Mipmap 正确生成，纹理尺寸不应超过实际需要。过大的纹理（如将 16×16 的方块纹理制作为 512×512）会造成不必要的内存浪费。

```properties
# Mipmap 级别与纹理尺寸关系
# 在 options.txt 中配置
mipmapLevels=4  # 0-4，级别越高远处纹理越平滑

# 512x512 纹理在 mipmap=4 时的各级尺寸：
# Level 0: 512×512 (原始)
# Level 1: 256×256
# Level 2: 128×128
# Level 3: 64×64
# Level 4: 32×32
```

### 1.4 不同纹理类型的推荐尺寸

```
方块纹理 (blocks/):
  ├── 基础方块: 与包的基准分辨率一致（如128x包则128x128）
  ├── 特殊方块（旗帜、盾牌等）: 可能需要更高分辨率
  └── 连接纹理（CTM）: 取决于 CTM 方案

物品纹理 (items/):
  ├── 工具/武器: 与包的基准分辨率一致
  ├── 食物: 与包的基准分辨率一致
  └── 地图: 128x128（原版）

实体纹理 (entity/):
  ├── 小型实体（蝙蝠等）: 64x32 原生
  ├── 中型实体（僵尸等）: 64x64 原生
  ├── 大型实体（末影龙等）: 256x256 原生
  └── 玩家皮肤: 64x64 原生

GUI 纹理 (gui/):
  ├── 背包界面: 256x256 原生
  ├── 标题画面: 可变
  └── 按钮/图标: 通常在一张大图集中
```

## 2. 文件格式

### 2.1 图像格式

Minecraft 资源包中的纹理**必须使用 PNG 格式**（.png）。

**格式要求**：
- 文件扩展名：`.png`（小写）
- PNG 类型：PNG-8 或 PNG-32（推荐 PNG-32 以支持完整 Alpha 通道）
- 色彩模式：RGBA（红、绿、蓝、Alpha透明度）
- 位深度：8位/通道（即 32位 RGBA）
- 压缩：PNG 无损压缩（Deflate）
- 隔行扫描：不使用（Non-interlaced）
- ICC 配置文件：不嵌入（避免兼容性问题）

### 2.2 文件命名规范

**命名规则**：
- 仅使用小写字母、数字、下划线（`_`）和连字符（`-`）
- 不使用空格、中文、特殊字符
- 不使用大写字母（Minecraft 的资源路径区分大小写，原版全小写）
- 保持与原版命名一致（替换纹理时）

```
✅ 正确命名：
stone.png
diamond_sword.png
creeper.png
oak_planks.png
bricks.png

❌ 错误命名：
Stone.png          ← 大写
Diamond Sword.png  ← 空格
石头.png           ← 中文字符
stone (1).png      ← 括号和空格
```

### 2.3 Alpha 通道要求

PNG-32 格式的 Alpha 通道对 Minecraft 至关重要：

```python
# Alpha 通道技术规范
alpha_spec = {
    "完全不透明": 255,    # 0xFF - 方块纹理通常使用
    "完全透明": 0,        # 0x00 - 不可见区域
    "半透明范围": "1-254", # 用于树叶、玻璃等特殊效果
}

# Minecraft 对半透明的处理方式
transparency_modes = {
    "方块纹理": {
        "不透明方块": "Alpha 必须为 255，否则可能出现渲染错误",
        "透明方块（玻璃等）": "使用 0 或 255，避免中间值",
        "半透明方块（冰等）": "可以使用中间 Alpha 值",
    },
    "物品纹理": {
        "普通物品": "背景必须完全透明（Alpha=0）",
        "光效物品": "可使用半透明产生发光效果",
    },
    "实体纹理": {
        "标准实体": "通常全部不透明",
        "幽灵类实体": "可使用半透明",
    },
}
```

## 3. 色彩规范

### 3.1 Minecraft 色彩风格

Minecraft 的视觉风格具有以下特征：
- **低分辨率像素艺术**：即使在高清包中也应保持像素艺术的清晰感
- **有限的色彩数量**：每个纹理通常使用较少的颜色种类
- **清晰的边缘**：像素边缘干净利落，避免模糊
- **一致的光照方向**：从左上方照射（顶部最亮，右侧次之，前方最暗）

### 3.3 光影处理

Minecraft 方块纹理遵循固定的光照方向：

```
光照方向示意：
        ↙ 光源方向（左上方）

   ┌─────────────────┐
   │ 亮面  │  中间调  │   顶面：最亮（面向光源）
   │       │         │   左面：较亮（部分面向光源）
   ├───────┼─────────│   前面：中等
   │ 中间  │  暗面   │   右面：较暗（背向光源）
   │       │         │   底面：最暗（完全背向光源）
   └─────────────────┘
```

**像素级光影规范**：
- 顶部边缘：使用最亮的颜色值
- 左侧边缘：使用较亮的颜色值
- 中心区域：使用基础颜色值
- 右侧和底部凹陷：使用较暗的颜色值
- 凹凸细节：通过明暗对比创造立体感

### 3.4 抗锯齿处理

Minecraft 纹理通常**不使用传统抗锯齿**，因为低分辨率下抗锯齿会导致纹理模糊。但在高清资源包中，适度的抗锯齿可以改善视觉效果：

```python
# 抗锯齿策略
anti_aliasing_guidelines = {
    "16x-32x（原生/低清）": {
        "策略": "不使用抗锯齿",
        "原因": "像素数量有限，模糊会降低清晰度",
    },
    "64x-128x（中高清）": {
        "策略": "选择性使用",
        "方法": "在对角线边缘使用1像素的过渡色",
        "示例": "圆弧边缘、倾斜线条",
    },
    "256x+（超高清）": {
        "策略": "适度使用",
        "方法": "2-3像素的过渡带",
        "注意": "保持像素艺术的整体风格，不要过度平滑",
    },
}
```

## 4. 透明度处理

### 4.1 Alpha 通道类型

Minecraft 支持三种透明度模式：

```
模式1：完全不透明（Opaque）
  Alpha = 255 (0xFF)
  用途：大多数方块（石头、泥土、木头等）
  渲染：不透明渲染管线，性能最优

模式2：完全透明（Cutout）
  Alpha = 0 或 255（二值化）
  用途：树叶、铁栏杆、花、草等
  渲染：使用 Alpha Test（阈值通常为 0.1），不支持半透明
  注意：中间 Alpha 值会被当作完全不透明或完全透明

模式3：半透明（Translucent）
  Alpha = 0-255（任意值）
  用途：玻璃、冰、水、灵魂沙等
  渲染：半透明渲染管线，需要深度排序，性能开销最大
  注意：可能出现排序错误导致的视觉异常
```

### 4.2 半透明纹理的注意事项

```python
# 半透明渲染的常见问题及解决方案
transparency_issues = {
    "排序错误": {
        "问题": "半透明面的渲染顺序不正确，导致后面的内容被错误遮挡",
        "缓解": "使用简单的几何形状，避免复杂的半透明重叠",
    },
    "面剔除异常": {
        "问题": "半透明方块背面被剔除，能看到方块内部",
        "缓解": "确保半透明纹理的两面都正确渲染",
    },
    "与粒子重叠": {
        "问题": "粒子在半透明方块前后闪烁",
        "缓解": "这是引擎限制，无法完全解决",
    },
}
```

## 5. 布局规范

### 5.1 方块纹理布局

方块纹理是 1:1 的正方形，通常采用以下布局模式：

```
普通方块布局（如石头）：
┌────────────┐
│            │
│   16x16    │  单一纹理，无需特殊布局
│            │
└────────────┘

可旋转方块布局（如铁砧）：
┌────────────┐
│   顶部面   │  可能需要单独的面纹理
│   16x16    │
└────────────┘

连接纹理布局（如玻璃）：
┌───┬───┬───┐
│ 0 │ 1 │ 2 │  3x3 或更大的图集
├───┼───┼───┤  每个子图代表不同的连接状态
│ 3 │ 4 │ 5 │
├───┼───┼───┤  需要 OptiFine 连接纹理支持
│ 6 │ 7 │ 8 │
└───┴───┴───┘
```

### 5.2 物品纹理布局

物品纹理同样是 1:1 正方形，但物品模型允许更灵活的 UV 映射：

```
工具/武器纹理布局：
┌────────────┐
│    刃部     │
│────────────│  工具纹理通常垂直排列
│    手柄     │  刃部在上，手柄在下
│            │
└────────────┘

食物纹理布局：
┌────────────┐
│            │
│   食物图   │  居中放置
│            │
└────────────┘
```

### 5.3 实体纹理布局

实体纹理的布局最为复杂，因为它需要与3D模型的UV映射精确对应：

```
标准人形实体纹理（如僵尸）：
┌────────┬────────┬────────┬────────┐
│ 头部   │ 头部   │ 头部   │ 头部   │
│ (正面) │ (背面) │ (左面) │ (右面) │
├────────┼────────┼────────┼────────┤
│ 头部   │ 头部   │        │        │
│ (顶面) │ (底面) │  未使用 │  未使用 │
├────────┼────────┼────────┼────────┤
│ 身体   │ 身体   │ 身体   │ 身体   │
│ (正面) │ (背面) │ (左面) │ (右面) │
├────────┼────────┼────────┼────────┤
│ 右臂   │ 右臂   │ 左臂   │ 左臂   │
│ (正面) │ (背面) │ (正面) │ (背面) │
├────────┼────────┼────────┼────────┤
│ 右腿   │ 右腿   │ 左腿   │ 左腿   │
│ (正面) │ (背面) │ (正面) │ (背面) │
└────────┴────────┴────────┴────────┘

```

## 6. 动画规格

### 6.1 动画纹理基础

Minecraft 支持帧动画纹理，通过垂直堆叠帧实现：

```
动画纹理结构：
┌────────────┐  第0帧 (16x16)
├────────────┤  第1帧 (16x16)
├────────────┤  第2帧 (16x16)
├────────────┤  第3帧 (16x16)
├────────────┤  ...
├────────────┤  第N帧 (16x16)
└────────────┘

总高度 = 16 × 帧数
宽度保持不变（16px 或对应高清倍率）
```

**常见动画纹理尺寸**：
- 火把火焰：16×112（7帧）
- 岩浆：16×512（32帧）
- 海晶石灯：16×256（16帧）
- 红石火把：16×256（16帧）
- 水面：16×512（32帧）

### 6.2 .mcmeta 动画配置

动画纹理需要同名的 `.mcmeta` 配置文件来控制播放行为：

**基础格式**：
```json
{
  "animation": {
    "frametime": 1,
    "frames": []
  }
}
```

**完整参数说明**：

```json
{
  "animation": {
    "frametime": 2,
    "frametime": 2,
    "interpolate": false,
    "frames": [
      0,
      1,
      2,
      { "index": 3, "time": 10 },
      4,
      5
    ]
  }
}
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `frametime` | int | 1 | 默认帧持续时间（游戏刻，1刻=50ms） |
| `interpolate` | bool | false | 是否在帧之间进行插值过渡 |
| `frames` | array | [0,1,2,...] | 帧序列，空数组则按顺序播放所有帧 |

**帧序列格式**：
```json
{
  "frames": [
    0,                          // 整数：帧索引，使用默认frametime
    1,
    { "index": 2, "time": 5 },  // 对象：指定帧索引和自定义持续时间
    3,
    { "index": 4, "time": 20 }  // 不同帧可以有不同的持续时间
  ]
}
```

### 6.3 帧率计算

```python
# 帧率计算公式
def calculate_fps(frametime):
    """
    frametime: 每帧持续的游戏刻数（1刻 = 50毫秒）
    返回: 每秒帧数
    """
    return 20 / frametime

# 常见配置
frametime_configs = {
    1:  {"fps": 20, "description": "快速动画（火焰、岩浆）"},
    2:  {"fps": 10, "description": "中速动画（红石火把）"},
    4:  {"fps": 5,  "description": "慢速动画（海晶石灯）"},
    10: {"fps": 2,  "description": "极慢动画（某些装饰方块）"},
    20: {"fps": 1,  "description": "每秒1帧（缓慢变换）"},
}

# 帧持续时间（秒）= frametime × 0.05
# 总动画时长 = sum(每帧的frametime) × 0.05 秒
```

### 6.4 帧插值

当 `interpolate` 设置为 `true` 时，Minecraft 会在相邻帧之间进行线性插值：

```json
{
  "animation": {
    "frametime": 2,
    "interpolate": true,
    "frames": [0, 1, 2, 3]
  }
}
```

插值效果：
- 帧0到帧1之间：生成中间过渡帧（基于像素颜色的线性混合）
- 过渡帧数量取决于 `frametime` 的值
- 适用于需要平滑过渡的动画（如昼夜循环、颜色渐变）

### 6.5 动画纹理 .mcmeta 文件命名

```
纹理文件名              → mcmeta 文件名
stone.png              → stone.png.mcmeta
water_still.png        → water_still.png.mcmeta
lava_still.png         → lava_still.png.mcmeta
campfire_fire.png      → campfire_fire.png.mcmeta
```

**重要**：`.mcmeta` 文件名必须是 `<纹理文件名>.png.mcmeta`，而不是 `<纹理文件名>.mcmeta`。

### 7.2 命名模式

Minecraft 的纹理命名遵循以下模式：

```
方块纹理命名模式：
  <方块名>.png                    → 单一面纹理（如 stone.png）
  <方块名>_<面>.png               → 多面方块（如 grass_block_top.png）
  <方块名>_still.png              → 静态动画帧（如 water_still.png）
  <方块名>_flow.png               → 流动动画帧（如 water_flow.png）

物品纹理命名模式：
  <物品名>.png                    → 标准物品（如 diamond_sword.png）
  <物品名>_<变体>.png             → 特殊变体（如 filled_map.png）

实体纹理命名模式：
  <实体名>.png                    → 简单实体（如 creeper.png）
  <实体名>/<实体名>.png           → 复杂实体（如 ender_dragon/dragon.png）
  <实体名>_<变体>.png             → 变体（如 cat_siamese.png）
```

### 8.2 内存优化

```python
# GPU 内存占用计算
def calculate_texture_memory(width, height, bpp=32):
    """
    计算纹理在 GPU 中占用的内存（字节）
    bpp: 每像素位数（RGBA = 32）
    """
    base_size = width * height * (bpp / 8)

    # Mipmap 额外内存（约 33%）
    mipmap_size = base_size * 0.33

    return base_size + mipmap_size

# 示例：不同分辨率的内存占用
memory_usage = {
    "16x16":   calculate_texture_memory(16, 16),     # ~1.06 KB
    "32x32":   calculate_texture_memory(32, 32),     # ~4.22 KB
    "64x64":   calculate_texture_memory(64, 64),     # ~16.9 KB
    "128x128": calculate_texture_memory(128, 128),   # ~67.5 KB
    "256x256": calculate_texture_memory(256, 256),   # ~270 KB
    "512x512": calculate_texture_memory(512, 512),   # ~1.08 MB
}

# 总内存占用估算（一个 512x 资源包）
# 假设约 1000 个方块纹理 + 500 个物品纹理 + 200 个实体纹理
# = 1000 × 1.08MB + 500 × 1.08MB + 200 × 1.08MB ≈ 1.8 GB
```

## 9. 常见问题排查

### 9.1 纹理不显示（紫黑棋盘格）

```
症状：纹理显示为紫黑色棋盘格（missing texture）
原因排查：
  1. 文件路径错误 → 检查 assets/<namespace>/textures/ 路径
  2. 文件名大小写错误 → 确保全小写
  3. 文件名拼写错误 → 与模型 JSON 中的引用对比
  4. PNG 格式损坏 → 用图像编辑器重新导出
  5. 不支持的格式 → 确保是标准 PNG（非 APNG、PNG-8 无 Alpha 等）
```

### 9.2 纹理扭曲/拉伸

```
症状：纹理在模型上显示扭曲或拉伸
原因排查：
  1. UV 坐标不匹配 → 检查模型 JSON 中的 UV 值
  2. 纹理尺寸不是 2 的幂次方 → 调整尺寸
  3. 纹理尺寸与模型预期不匹配 → 检查 textureSize 属性
  4. Mipmap 导致的边缘渗色 → 确保 UV 边界正确
```

### 9.3 动画不播放

```
症状：动画纹理静止不动
原因排查：
  1. 缺少 .mcmeta 文件 → 创建同名的 .png.mcmeta 文件
  2. .mcmeta 文件名错误 → 确保格式为 <纹理名>.png.mcmeta
  3. JSON 语法错误 → 使用 JSON 验证器检查
  4. 纹理高度不是宽度的整数倍 → 调整纹理高度
  5. 帧索引超出范围 → 检查 frames 数组中的索引值
```

### 9.4 半透明纹理渲染异常

```
症状：半透明纹理出现闪烁、消失或显示错误
原因排查：
  1. 排序问题 → 这是引擎限制，无法完全解决
  2. Alpha 值过低 → 增加 Alpha 值（至少 10+）
  3. 多层半透明重叠 → 减少重叠层数
  4. 着色器冲突 → 检查是否使用了影响透明度的着色器
```

### 9.5 纹理边缘渗色（Bleeding）

```
症状：纹理边缘出现相邻纹理的颜色条纹
原因：
  Mipmap 或纹理过滤时采样到了纹理边缘之外的像素
解决方案：
  1. 在 UV 坐标中添加微小的内缩（inset）
  2. 扩展纹理边缘像素（边缘像素向外延伸 1-2 像素）
  3. 使用纹理图集时确保子图之间有足够间距
```

### 10.3 纹理检查

```bash
# 检查纹理尺寸是否为 2 的幂次方
for f in $(find assets/ -name "*.png"); do
    size=$(identify -format "%wx%h" "$f")
    w=$(echo $size | cut -d'x' -f1)
    h=$(echo $size | cut -d'x' -f2)
    if (( w & (w - 1) )) || (( h & (h - 1) )); then
        echo "非2的幂次方: $f ($size)"
    fi
done

# 检查 PNG 文件是否损坏
for f in $(find assets/ -name "*.png"); do
    if ! identify "$f" > /dev/null 2>&1; then
        echo "损坏: $f"
    fi
done
```
