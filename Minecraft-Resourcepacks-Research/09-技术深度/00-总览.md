## Minecraft 资源加载管线

理解资源包如何被加载和应用，是进行高级开发的基础。以下是 Minecraft 资源加载管线的完整流程。

### 1. 资源包发现与注册

```
游戏启动
  │
  ├─ 扫描 .minecraft/resourcepacks/ 目录
  │    ├─ 检测每个 .zip 文件和文件夹
  │    ├─ 读取 pack.mcmeta 获取包元数据
  │    └─ 读取 pack.png 获取预览图
  │
  └─ 加载用户配置（options.txt 中的 resourcePacks 字段）
       └─ 确定激活的资源包列表及其优先级顺序
```

### 2. 资源包合并

Minecraft 允许同时激活多个资源包，系统通过**覆盖合并**机制处理冲突：

```
激活顺序（从低到高优先级）：
  vanilla (内置默认)
    ↓ 被覆盖
  资源包 A (底层)
    ↓ 被覆盖
  资源包 B (中层)
    ↓ 被覆盖
  资源包 C (顶层，最高优先级)
```

**合并规则**：
- 同名资源：高优先级包覆盖低优先级包
- 唯一资源：各包的独有资源均被保留
- 标签系统（1.20.2+）：支持 `pack_format` 区分不同版本的资源

### 4. 资源加载时序

```java
// 伪代码：资源加载管线简化表示
class ResourceManager {
    void loadResources(List<ResourcePack> activePacks) {
        // 阶段1：构建资源索引
        ResourceIndex index = buildIndex(activePacks);

        // 阶段2：加载纹理图集
        TextureAtlas atlas = stitchTextures(index.getAllTextures());

        // 阶段3：编译模型
        Map<ResourceLocation, Model> models = compileModels(index);

        // 阶段4：解析方块状态映射
        Map<BlockState, Model> blockStateMap = parseBlockStates(index, models);

        // 阶段5：加载着色器
        ShaderManager shaders = loadShaders(index);

        // 阶段6：初始化粒子系统
        ParticleManager particles = loadParticles(index);

        // 阶段7：加载语言文件
        LanguageManager lang = loadLanguages(index);
    }
}
```

### 5. 纹理图集（Texture Atlas）构建

Minecraft 不会逐个加载纹理，而是将多个纹理合并到纹理图集中以优化渲染性能：

```
纹理图集构建过程：
  1. 收集所有需要的纹理文件
  2. 根据尺寸和类型分组
  3. 使用打包算法（bin packing）排列到图集中
  4. 记录每个纹理在图集中的 UV 坐标映射
  5. 上传至 GPU 纹理缓冲区
```

图集类型（1.19.4+ 通过 atlases/ 目录配置）：
- `blocks`：所有方块和大多数物品纹理
- `entities`：实体纹理
- `mob_effects`：状态效果图标
- `paintings`：画作纹理
- `signs`：告示牌纹理
- `banner_patterns`：旗帜图案
- `shield_patterns`：盾牌图案
- `beds`：床纹理
- `chests`：箱子纹理
- `shulker_boxes`：潜影盒纹理
- `decorated_pot`：装饰罐纹理

## Minecraft 渲染管线概述

### 1. 整体渲染流程

```
游戏主循环
  │
  ├─ 世界渲染
  │    ├─ 视锥体剔除（Frustum Culling）
  │    ├─ 遮挡剔除（Occlusion Culling）
  │    ├─ 区块渲染（Chunk Rendering）
  │    │    ├─ 半透明排序（Translucency Sorting）
  │    │    ├─ 顶点缓冲区构建（VertexBuffer Building）
  │    │    └─ 渲染批次提交（Draw Call Batching）
  │    ├─ 实体渲染（Entity Rendering）
  │    │    ├─ 模型变换（Model Transform）
  │    │    ├─ 骨骼动画（Skeletal Animation）
  │    │    └─ 纹理绑定（Texture Binding）
  │    └─ 粒子渲染（Particle Rendering）
  │
  ├─ GUI 渲染
  │    ├─ HUD 元素
  │    ├─ 背包界面
  │    └─ 文本渲染
  │
  └─ 后处理（Post-Processing）
       ├─ 泛光（Bloom）
       ├─ 景深（Depth of Field）
       └─ 色调映射（Tone Mapping）
```

### 2. 方块渲染机制

方块渲染是 Minecraft 渲染管线中最核心的部分：

```
方块渲染流程：
  BlockState
    ↓ 查询 blockstates/*.json
  BlockStateDefinition（变体/multipart）
    ↓ 解析模型引用
  BlockModel（models/block/*.json）
    ↓ 应用父模型继承
  Resolved Model（完全展开的模型）
    ↓ 应用 display 变换
  Baked Model（烘焙后的模型）
    ↓ 纹理映射 + UV 展开
  Vertex Data（顶点数据）
    ↓ 批次合并
  Draw Call（GPU 渲染调用）
```

**方块模型烘焙**是关键步骤，发生在资源加载阶段：
1. 解析完整的模型继承链
2. 将所有纹理变量替换为实际纹理路径
3. 将相对 UV 坐标转换为绝对 UV 坐标
4. 计算面的法线和光照
5. 生成最终的顶点缓冲区数据

### 3. 实体渲染机制

实体渲染使用不同的管线：

```
实体渲染流程：
  Entity
    ↓ 查询实体类型
  EntityRenderer
    ↓ 获取模型
  EntityModel（骨骼层级结构）
    ↓ 应用动画
  Pose Stack（姿态栈）
    │  translate(x, y, z)    ← 位置偏移
    │  rotateX(angle)        ← X轴旋转
    │  rotateY(angle)        ← Y轴旋转
    │  rotateZ(angle)        ← Z轴旋转
    │  scale(x, y, z)        ← 缩放
    ↓
  ModelPart.render()        ← 逐部件渲染
    ↓
  顶点提交到 GPU
```

**OptiFine CEM** 通过拦截实体模型加载过程，在 EntityModel 层面注入自定义模型数据，从而实现对实体外观的完全自定义。

### 4. 渲染优化技术

Minecraft 采用多种优化技术：

| 技术 | 说明 | 对资源包的影响 |
|------|------|----------------|
| 纹理图集 | 合并纹理减少绑定切换 | 纹理尺寸影响图集效率 |
| 顶点缓冲区 | 批量渲染同材质方块 | 模型复杂度影响顶点数量 |
| 视锥体剔除 | 不可见区块不渲染 | 无直接影响 |
| 遮挡查询 | 被遮挡方块不渲染 | 无直接影响 |
| 区块重编译缓存 | 只重编译变化的区块 | 纹理动画触发重编译 |
| Mipmap | 远距离使用低分辨率纹理 | 影响纹理清晰度 |
| 各向异性过滤 | 斜角观察时改善纹理质量 | 影响纹理视觉效果 |

### 5. 着色器系统

Minecraft 的着色器分为两层：

**核心着色器**（内置，资源包不可替换）：
- Block 着色器：方块渲染
- Entity 着色器：实体渲染
- Particle 着色器：粒子渲染
- Sky 着色器：天空渲染

**后处理着色器**（可通过 `shaders/post/` 自定义）：
- 模糊效果
- 色彩校正
- 泛光效果
- 自定义全屏效果
