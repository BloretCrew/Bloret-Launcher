结论摘要

项目功能面完整，已有下载取消、更新包校验、插件包路径防穿越、配置原子替换、Live 消息去重和多平台路径兼容等正向控制；但当前发布安全边界和认证链路仍存在高影响风险。最高优先级是仓库内的私钥、Passport 客户端密钥及 OAuth 明文降级，其次是插件权限并非隔离边界、远程启动路径校验不一致，以及发布构建可在没有签名时成功结束。

Linux 环境完成了 Python 语法编译检查和标准库 unittest 发现；测试发现 67 项，其中 64 项通过、3 项因环境/平台依赖导入失败。pytest 不可用，QML 检查因缺少 PySide6 无法启动。当前环境没有可用的浏览器或桌面 GUI 验证工具，因此页面逐页交互、Windows、macOS、FreeBSD、真实高 DPI、主题和键盘操作均应标为“未验证”，不能视为通过。

优先级修复清单

P0 F-01 仓库包含代码签名私钥

现象：sign/root.pvk 存在且被 Git 追踪；代码签名脚本把它作为回退凭据。

证据：sign/root.pvk；.github/scripts/windows-codesign.ps1:12-13,204-208；.gitignore:8-18。

复现：test -f sign/root.pvk && git ls-files sign/root.pvk。

根因/影响：私钥随仓库分发，持有仓库访问权者可能伪造 Authenticode 签名。若曾用于可信发布链，发布身份已不可继续信任。

建议：立即轮换/撤销证书，清理历史；仅用 CI Secret 或外部签名服务；官方构建缺证书必须失败。回归：CI 扫描拒绝 *.pvk/*.pem/*.pfx/*.p12 及已知密钥路径。

P1 F-02 Passport 应用密钥硬编码在客户端

证据：modules/web.py:1323,1468 的 app_secret 常量随客户端发送。

影响：任何获得发行包的人都可复用应用凭据，无法按安装实例撤销。建议：轮换旧密钥，改用 PKCE/服务端短期挑战，客户端不再持有服务端秘密。回归：秘密扫描和不携带静态密钥的 OAuth 集成测试。

P1 F-03 OAuth 回退把认证数据降级发送到 HTTP

证据：modules/web.py:1340-1356 构造 http://host:20000/app/verify，发送 code 和 app_secret。

复现：让 HTTPS 验证返回错误，再监听端口 20000，触发回调即可观察明文请求。建议：远程认证只允许 HTTPS；禁止 HTTPS→HTTP 降级；HTTP 仅限明确的本机开发模式。回归：模拟 HTTPS 失败时断言没有 HTTP 请求。

P1 F-04 缺少 OAuth code 仍返回成功页面

证据：modules/web.py:1311-1321,1435-1443。无 code 时进入成功页面分支。

复现：GET /login/Bloret-PassPort。影响：用户看到虚假的登录成功，回调失败被掩盖。建议/回归：返回 400 或失败页，不改账号状态，并测试拒绝、过期和错误回调。

P1 F-05 远程启动使用未充分约束的版本路径

证据：modules/web.py:748-766 接收 version；modules/launch.py:250-268 直接拼接版本目录；服务层虽在 modules/services/versions_service.py:62-73 做包含校验但未覆盖该调用链。

复现：开启 Web Remoter 后提交 version=../../outside 或绝对路径。影响：可能读取并执行 versions 根目录外的本地元数据。建议：统一调用带 Path.resolve() 和 commonpath/父目录约束的解析器，覆盖绝对路径和 symlink。回归：Web、Backend、launch、download 四类入口参数化测试。

P1 F-06 OOBE PassPort 跳转索引错误

证据：qml/main.qml:607-614 使用 navItems[1]，但该项是 Blora Agent，PassPort 是索引 2；同时写入未声明的 currentPage，而其他路径使用 navigationView.push()。

影响：首次启动用户可能被送到错误页面或触发 QML 运行时错误。建议/回归：按稳定 ID 查找 PassPort 并使用统一导航 API，首次启动登录/跳过/返回路径各测一次。

P1 F-07 OOBE Java 安装失败会卡死向导

证据：qml/OOBEOverlay.qml:596-621,792-810 与 qml/OOBE.qml:590-610,710-730 设置安装状态却只处理成功信号。

影响：失败时按钮可能永久禁用，用户没有错误、重试或恢复路径。建议/回归：增加失败信号、超时、可重试状态，并模拟下载失败、取消和无 Java 场景。

P1 F-08 OOBE 账号同步用固定 2 秒计时器伪造完成

证据：qml/OOBEOverlay.qml:545-553,64-72、qml/OOBE.qml:530-540。

影响：慢请求会被误判为空，失败与无账号不可区分。建议/回归：以明确的 started/succeeded/failed/cancelled 信号结束同步，并覆盖慢网络和失效会话。

P1 F-09 BBBS 失败仅写日志，页面无错误和重试

证据：qml/pages/BBBS.qml:30-42 的 onBbbsErrorOccurred 只停止 loading 并 console.log。

影响：网络失败会被看成空列表或半加载页面。建议/回归：显示错误摘要、保留已有数据、提供重试，分别测试 4xx/5xx/坏 JSON/超时。

架构与数据流

UI (QML pages/components/OOBE/editor)
  → Backend QObject in Bloret-Launcher.py (Slots/Signals, legacy orchestration)
    → modules/services (config/content/launch/live/versions)
    → modules (install, download, versions, modrinth, mrpack, plugin, Passport, BBBS/Live, EasyTier, Java)
      → filesystem / network / child processes / Minecraft runtime

额外入口：modules.web import side effect → localhost web API → same shared globals/config/process state
插件入口：PluginHost → in-process Python import + QML contributions/theme/tools

主要分层违例是 Backend 和 legacy modules 仍直接拼接路径、管理共享进程字典和读改写配置；Web API 线程与 Qt/UI 线程共享状态；插件宿主的权限层位于执行之后而不是隔离边界。
